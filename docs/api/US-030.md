# API Design — US-030 Cổng phê duyệt thủ công cho production

> **Trạng thái:** `ANALYSIS_READY — chờ chủ dự án duyệt nội dung`
> **Epic:** `EPC-08` · **Nhánh:** `feature/US-030-prod-approval` · **Ngày:** `2026-11-25`
> **Người soạn:** AI assistant · **Người duyệt:** Chủ dự án
>
> Không tạo HTTP API công khai. Tài liệu này đặc tả hợp đồng vận hành của
> GitHub Actions và GitHub Environment theo yêu cầu bổ sung của chủ dự án.

## 1. Mục tiêu

- Vấn đề cần giải quyết: workflow hiện có có thể chuyển traffic production tự động sau smoke test, không có điểm phê duyệt thủ công.
- Kết quả mong đợi: production chỉ bắt đầu triển khai sau khi staging đã triển khai thành công đúng cùng Git SHA và người được chỉ định duyệt qua GitHub Environment `production`.
- Phạm vi: workflow backend, kiểm tra staging run cùng SHA, cổng Environment trước mọi bước production, kiểm thử hợp đồng và audit approval sẵn có của GitHub.
- Ngoài phạm vi: tạo/sửa endpoint ứng dụng, thay đổi hạ tầng Azure, tự cấu hình reviewer trên GitHub Settings, hoặc chạy thử deploy production.

## 3. Existing Architecture

- Backend hiện có: FastAPI được triển khai lên Azure Container Apps; smoke test kiểm tra `/health` và `/version`.
- Frontend hiện có: frontend tĩnh trên Cloudflare Pages; không tham gia quyết định promotion backend của US-030.
- Module liên quan: `.github/workflows/deploy-backend.yml`, `scripts/smoke_test.py`, `tests/test_us029_deploy_workflow.py` và `tests/test_us030_production_approval.py`.
- Cách chạy hiện tại: push `develop` chạy deployment staging; push `main` chạy deployment production. Workflow có job `verify-staging` kiểm tra successful staging run cùng SHA; job `deploy` phụ thuộc job này và chọn Environment theo nhánh.
- Quy ước response/error hiện có: không thay đổi HTTP response của ứng dụng. Lỗi preflight làm workflow thất bại với diagnostic; lỗi smoke/traffic giữ nguyên hành vi rollback của US-029.

## 6. Proposed API Changes

### 6.1. GitHub Actions workflow contract

- **Method:** N/A — trigger bằng `push` trên `develop` hoặc `main`.
- **Endpoint:** N/A — không tạo endpoint ứng dụng.
- **Purpose:** Chỉ cho phép job deployment production bắt đầu sau staging cùng SHA và khi GitHub Environment cho phép job tiếp tục.
- **Authentication:** GitHub Actions `GITHUB_TOKEN` cho truy vấn workflow runs; Azure OIDC chỉ được dùng trong job triển khai sau cổng Environment.
- **Authorization:** Preflight có `actions: read`; deploy job có `id-token: write`. Reviewer phải được cấu hình trong GitHub Environment `production`.
- **Path Parameters:** Không áp dụng.
- **Query Parameters:** Lời gọi GitHub Actions Runs API lọc `branch=develop`, `head_sha=GITHUB_SHA`, `status=success`, `per_page=1`.
- **Request Body:** Không áp dụng. Workflow dùng branch và SHA của event `push`.
- **Response:** GitHub JSON workflow-runs collection. Chỉ chấp nhận kết quả có `head_sha` bằng `GITHUB_SHA`, `head_branch=develop` và `conclusion=success`.
- **HTTP Status:** Không áp dụng cho endpoint ứng dụng. Workflow tiếp tục khi preflight thành công; nếu không có run hợp lệ, bước kiểm tra thoát khác `0`.
- **Validation:** Chỉ `main` cần preflight staging. Không có successful run cho đúng SHA thì fail-closed. Job `deploy` phải `needs: verify-staging` và dùng Environment `production` trên `main`.
- **Business Rules:** `BR-017`; staging phải được kiểm chứng trước và người dùng production không phải người kiểm thử đầu tiên.
- **Error Cases:** API lỗi/quyền `actions: read` thiếu hoặc không tìm thấy run thành công đều làm preflight thất bại; không được coi response rỗng/lỗi là thành công. Nếu Environment không được cấu hình required reviewers, GitHub có thể không chặn job; đây là cấu hình repository cần chủ repo xác minh.

## 7. Business Flow

```text
Push commit lên develop
  → verify-staging bỏ qua preflight production
  → deploy vào Environment staging
  → staging candidate được smoke test và promotion theo US-029

Push cùng commit lên main
  → verify-staging truy vấn successful run trên develop với đúng GITHUB_SHA
  → không tìm thấy run → dừng fail-closed, chưa chạy production job
  → tìm thấy run → deploy job chạm Environment production
  → GitHub chờ required reviewer trước mọi step build/deploy/traffic
  → reviewer duyệt → build candidate, smoke test, chuyển traffic theo US-029
  → GitHub lưu thông tin deployment review/audit theo khả năng lưu trữ của repository
```

Chính sách đã được chủ dự án chọn là **cùng SHA chính xác**, không so sánh tree hash. Nếu merge vào `main` tạo SHA mới, preflight sẽ chặn promotion dù tree giống nhau. Workflow chỉ tham chiếu tên Environment; required reviewers phải được cấu hình riêng trong GitHub Settings.

## 8. Security

| Mục | Giá trị |
|---|---|
| Authentication | `GITHUB_TOKEN` do Actions cấp cho preflight; Azure OIDC sau cổng Environment |
| Authorization | Preflight chỉ có `actions: read`; deploy chỉ có `contents: read` và `id-token: write` |
| Role được phép | Reviewer do chủ repo chỉ định trong Environment `production`; danh tính reviewer chưa được cung cấp trong backlog |
| Dữ liệu nhạy cảm | Git SHA, branch, workflow run metadata và danh tính/thời điểm duyệt; không cần secret mới |
| Giới hạn tần suất | GitHub REST API có rate limit; workflow chỉ truy vấn một lần cho production run |
| Không được đưa vào request | Không truyền token, Azure secret, actor ID hoặc dữ liệu người dùng trong query; token chỉ nằm trong `GH_TOKEN` của step |

## 14. Test Scenarios

| Loại | Mô tả | Dữ liệu |
|---|---|---|
| Happy path | Staging run cùng SHA có `conclusion=success`; production job chờ Environment reviewer rồi mới chạy step đầu | Workflow run metadata và `GITHUB_SHA`; GitHub Environment `production` |
| Validation | Không có run, SHA khác, branch khác hoặc staging run thất bại thì preflight không cho deploy tiếp | GitHub Actions Runs API result; mock/static workflow contract |
| Authorization | `GITHUB_TOKEN` chỉ có quyền `actions: read`; reviewer được kiểm tra bởi Environment protection | Workflow YAML và repository Environment settings |
| Business failure | Reviewer từ chối hoặc không phản hồi thì production job không chạy và traffic không đổi | GitHub deployment review status |
| Regression | Push `develop` vẫn tiếp tục staging; smoke-test, traffic shift và rollback US-029 giữ nguyên | `tests/test_us029_deploy_workflow.py`, `tests/test_us030_production_approval.py` |

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| Environment `production` chưa có required reviewers | Job có thể chạy mà không chờ người duyệt | Chủ repo cấu hình reviewer trong GitHub Settings và xác minh deployment protection trước khi bật promotion |
| SHA trên `main` khác SHA đã staging do merge commit | Production bị chặn dù code tree giống nhau | Giữ cùng commit khi promote; nếu chiến lược merge không đáp ứng, chủ dự án phải duyệt thay đổi chính sách |
| GITHUB_TOKEN thiếu `actions: read` hoặc GitHub API lỗi | Preflight thất bại | Cấp đúng quyền tối thiểu; giữ fail-closed và xem log workflow |
| Chưa chạy live approval flow | Chưa có bằng chứng người duyệt/thời điểm được lưu như yêu cầu | Sau khi cấu hình Environment, xác minh một workflow run có kiểm soát; không approve một lần triển khai production chỉ để thử |

## 17. Implementation Handoff

- **Backend nhận:** Không thay đổi endpoint hoặc service code; giữ nguyên `/health`, `/version`, `/predict`.
- **Frontend nhận:** Không áp dụng.
- **Tester nhận:** Chạy test hợp đồng; xác minh successful staging cùng SHA, trạng thái Waiting, approve/reject và audit người/thời điểm trên GitHub sau khi Environment được cấu hình.
- **Điều kiện bắt đầu code:** Tài liệu này cần được chủ dự án duyệt trước thay đổi tiếp theo; phần triển khai hiện có đã được thực hiện trên nhánh local theo các quyết định đã xác nhận. Không push hoặc chạy production deployment khi chưa được cho phép.
