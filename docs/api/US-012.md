## 1. Mục tiêu

- **Vấn đề:** Mô hình có kích thước lớn; nếu nạp lại trong request handler sẽ tăng latency và lãng phí tài nguyên cho từng request.
- **Kết quả mong đợi:** Mỗi lần khởi chạy ứng dụng nạp model trong FastAPI lifespan một lần, giữ instance trong `app.state.model`, chỉ báo health sẵn sàng sau khi load hoàn tất và ghi duration để hỗ trợ điều tra cold start.
- **Phạm vi:** Lifecycle nạp model hiện có, readiness qua `/health`, log thời gian load, và test tự động gửi 10 request `/predict`.
- **Ngoài phạm vi:** Không thêm endpoint hoặc schema HTTP; không thay đổi inference/preprocessing; không đặt ngưỡng latency; không đo cold start trên Azure (thuộc phạm vi benchmark riêng).

## 3. Existing Architecture

Đối chiếu repository ngày 2026-11-08:

- **Backend:** FastAPI service tại `src/vsl/service.py`; app lifespan là nơi nạp model.
- **Frontend:** Có web client riêng; không thuộc thay đổi US-012.
- **Module liên quan:** `src/vsl/service.py` (`lifespan`, `/health`, `/predict`), `src/vsl/config.py` (`get_model_path()`), `tests/test_health.py`, `tests/test_predict.py`.
- **Cách chạy:** ASGI runner, ví dụ `uvicorn src.vsl.service:app`; `TestClient` context được dùng để chạy startup/shutdown lifespan trong test.
- **Response/error hiện có:** `/health` trả `200` và `model_loaded: true` khi model đã sẵn sàng; trả `503` và `model_loaded: false` khi model chưa được nạp. `/predict` trả `503` nếu model chưa sẵn sàng. Không thay đổi các response này.
- **Model loader:** `keras.models.load_model(str(get_model_path()))`; model được giữ trong `app.state.model`.

## 6. Proposed API Changes

### 6.1. Public HTTP API

- **Method / Endpoint:** N/A — không thêm hoặc sửa endpoint.
- **Purpose:** Không có thay đổi hợp đồng HTTP trong US-012.
- **Authentication / Authorization:** Không đổi so với các endpoint hiện tại.
- **Path Parameters / Query Parameters / Request Body:** N/A.
- **Response / HTTP Status:** Không đổi. `/health` tiếp tục trả 200 khi model đã nạp và 503 khi chưa sẵn sàng; `/predict` tiếp tục trả 503 nếu model chưa sẵn sàng.
- **Validation / Business Rules:** Model phải được nạp trong lifespan trước khi app phục vụ request (BR-011).
- **Error Cases:** Lỗi load được log, `app.state.model` đặt về `None`; `/health` thể hiện degraded/503 và `/predict` không chạy inference.

### 6.2. Internal startup log contract

- **Scope:** Log nội bộ của `vsl.service`, không phải API công khai hay định dạng trao đổi với client.
- **Thành công:** Ghi một log INFO sau khi load xong, có trường `duration_ms=<number>` đo bằng `time.perf_counter()`.
- **Thất bại:** Ghi một log ERROR có `duration_ms=<number>` cùng lỗi load; model và version được đặt về `None`.
- **Đơn vị và độ chính xác:** Millisecond, định dạng thập phân ba chữ số trong message log.
- **Validation:** Test xác nhận có đúng một log duration cho startup thành công và giá trị parse được, không âm. Không có ngưỡng thời gian bắt buộc.
- **Error behavior:** Không giả lập trạng thái thành công khi load lỗi; ứng dụng tiếp tục ở trạng thái model chưa sẵn sàng theo behavior hiện có.

## 7. Business Flow

```text
Ứng dụng khởi động
  → FastAPI lifespan bắt đầu
  → ghi nhận perf_counter
  → gọi keras.models.load_model(get_model_path())
     ├─ thành công: lưu model tại app.state.model
     │              resolve model_version
     │              ghi INFO duration_ms
     └─ thất bại: ghi ERROR duration_ms và nguyên nhân
                   đặt app.state.model/model_version = None
  → lifespan yield; app bắt đầu phục vụ request
  → /health trả 200 nếu có model, nếu không trả 503
  → 10 request /predict dùng cùng app.state.model; không gọi load_model lại
  → shutdown: giải phóng app.state.model
```
