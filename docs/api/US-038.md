## 1. Mục tiêu
- Vấn đề: Quá trình build image cũ không có Dockerfile multi-stage, thẻ trôi nổi gây phình dung lượng và không tái lập được.
- Kết quả: `Dockerfile` multi-stage build, ghim base image digest, cố định `--platform linux/amd64`, tái sử dụng cache dependency, runtime không chứa compiler, và CI ghi lại kích thước image/thời gian build (BR-025).
- Phạm vi: `Dockerfile`, manifest runtime riêng, kiểm thử hợp đồng Docker, CI cache metrics. Ngoài phạm vi: đẩy image lên registry production (thuộc US-029).

## 6. Proposed Container Contract
- **Base image builder:** `python:3.12.7-slim-bookworm@sha256:60d9996b6a8a3689d36db740b49f4327be3be09a21122bd02fb8895abb38b50d`
- **Base image runtime:** `python:3.12.7-slim-bookworm@sha256:60d9996b6a8a3689d36db740b49f4327be3be09a21122bd02fb8895abb38b50d`
- **Target platform:** `linux/amd64`
- **Cache order:** `COPY requirements-runtime.txt` → cached `pip install` → `COPY src`
- **Python dependencies:** runtime-only pinned direct dependencies in `requirements-runtime.txt`; training and notebook packages are excluded from the image manifest.
- **Build cache:** BuildKit pip cache mount and GitHub Actions `type=gha`.
- **User:** `appuser` (non-root, UID 10001)
- **Port:** `8080`
- **Digest verification:** Docker Registry returned the pinned manifest-list digest for tag `3.12.7-slim-bookworm`; the manifest includes linux/amd64. No image build ran locally because Docker Engine was unavailable.
- **Validation limitation:** the selected CI test suite passes (70 tests), but the branch-wide Ruff check currently reports 11 pre-existing findings and Black reports 12 files needing formatting. Since the Docker job depends on the lint/test job, hosted CI will not reach the image build until those existing gates pass; those unrelated files were not reformatted in this US-038 change.

## 7. Business Flow
```
CI/CD kích hoạt Docker build
  → Tải layer base image đã ghim digest
  → Đọc cache gha
  → Cài phụ thuộc runtime vào /opt/venv ở stage builder, dùng BuildKit pip cache
  → Sao chép /opt/venv sang stage runtime
  → Tạo user không đặc quyền và expose cổng 8080
  → Ghi lại dung lượng image và thời gian build vào Step Summary
```

## 8. Security
- Non-root user: `appuser` ngăn chặn leo thang đặc quyền container.
- Loại bỏ toàn bộ trình biên dịch `gcc`, `g++`, header files khỏi image runtime cuối cùng.
