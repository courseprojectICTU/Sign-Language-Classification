# API Design — US-020 Azure Container Apps service với min-instances bằng 0

> **Trạng thái:** `ANALYSIS_READY`
> **Epic:** `EPC-05` · **Nhánh:** `feature/US-020` · **Ngày:** `2026-11-11`
> **Người soạn:** AI assistant · **Người duyệt:** Chủ dự án (chờ phê duyệt Cổng B)
>
> File này là **hợp đồng hạ tầng IaC (Terraform)** cho dịch vụ Azure Container Apps `vsl-api`.
> US-020 **không** tạo hoặc thay đổi HTTP endpoint Python trong `src/vsl/service.py`.
> Không sửa mã nguồn hay file Terraform cho đến khi tài liệu này được duyệt.

## 1. Mục tiêu

- **Vấn đề cần giải quyết:** Trên nhánh `develop`, thư mục `infra/` mới quản lý Terraform remote backend (`US-018`), ACR/OIDC/RBAC (`US-019`) và Billing Budget (`US-033`). Dịch vụ Container Apps staging (`cae-vsl-staging-std`, `vsl-api`, Log Analytics `workspace-rgvslstaging8EBp`, User Assigned Managed Identity `id-vsl-api-pull` và role `AcrPull`) được tạo thủ công trước đó nên chưa nằm trong Terraform state, đang chạy với `minReplicas = 1`, `maxReplicas = 2`, chưa khai báo HTTP health probes tới `/health` và chưa khai báo biến môi trường `VSL_MODEL_PATH` trong mã nguồn hạ tầng.
- **Kết quả mong đợi sau US-020:** Quản lý toàn bộ ngăn xếp Azure Container Apps trong Terraform root `infra/` với chế độ Consumption (tính phí theo request), `min_replicas = 0`, `max_replicas = 3`, `1.0` vCPU, `2Gi` RAM (trong khoảng `1–2 GiB`), `termination_grace_period_seconds = 60`, `revision_mode = "Multiple"` (tương thích rollback `US-031`), healthcheck HTTP trỏ `/health` trên cổng `8080`, biến môi trường `VSL_MODEL_PATH` và `VSL_ALLOWED_ORIGINS`; import tài nguyên staging hiện có vào remote state `vslstate2026`, apply `min_replicas = 0` và nghiệm thu `AC-020-01`, `AC-020-02`.
- **Phạm vi:** `infra/container_app.tf`, `infra/variables.tf`, `infra/identity.tf`, `infra/outputs.tf`, `infra/environments/staging.tfvars`, `infra/environments/production.tfvars`, `infra/README.md`, `tests/test_us020_container_app.py`, cập nhật assertion tương ứng trong `tests/test_us019_azure_terraform.py`, đồng bộ tài liệu trạng thái/bàn giao/runbook.
- **Ngoài phạm vi:** Không sửa API FastAPI `src/vsl/`, không sửa `web/config.js` hay cấu hình Cloudflare Pages (`US-024`), không thêm workflow CD tự động (`US-029`), không tách thành module/state riêng cho từng môi trường (`US-021` sẽ rebase sau theo kiến trúc này), không apply lên production (`production.tfvars` giữ placeholder), không xóa các resource hiện hữu khác trong `rg-vsl-staging` như `vslacr4751`, `asp-vsl`, `vsl-vietnam`, và không tắt `admin_enabled = true` trên ACR (`US-019`).

## 3. Existing Architecture

Kiểm chứng trực tiếp từ repository và Azure Resource Group `rg-vsl-staging` ngày `2026-11-11`:

- **Backend hiện có (`src/vsl/service.py`, `Dockerfile`):**
  - FastAPI lắng nghe cổng `8080` (`uvicorn src.vsl.service:app --host 0.0.0.0 --port 8080`).
  - `Dockerfile` sao chép model vào `/app/train/vsl_cnn_pose_keras.h5` và cấu hình Docker `HEALTHCHECK` tới `http://localhost:8080/health`.
  - [src/vsl/config.py](../../src/vsl/config.py) ưu tiên đọc biến môi trường `VSL_MODEL_PATH`; nếu không đặt thì fallback về `<PROJECT_ROOT>/train/vsl_cnn_pose_keras.h5`.
  - `GET /health` trả HTTP `200` (`{"status": "ok", "model_loaded": true, "model_version": ...}`) khi model đã nạp xong qua Lifespan, hoặc HTTP `503` (`model_loaded: false`) khi chưa/không nạp được model.
  - `CORSMiddleware` đọc danh sách origin chính xác từ `VSL_ALLOWED_ORIGINS` (không chấp nhận wildcard `*`).
- **Hạ tầng Terraform trên `develop` (`infra/`):**
  - `infra/versions.tf`, `infra/provider.tf`: `terraform >= 1.5.0`, `azurerm ~> 4.0` (đã cache `4.81.0`), `azuread ~> 3.0`, `subscription_id = var.subscription_id`, `resource_provider_registrations = "none"`.
  - `infra/backend.tf`: remote backend `azurerm` (Container `tfstate` trong `vslstate2026`, key `sign-language-classification/staging.tfstate`).
  - `infra/registry.tf`: quản lý ACR `vslacr3795` (`Basic`, `admin_enabled = true`, `prevent_destroy = true`) cùng identity/task cleanup giữ 3 tag.
  - `infra/identity.tf`: đang dùng `data "azurerm_container_app" "vsl_api"` làm `scope` cho `azurerm_role_assignment.deployment_app` (`Container Apps Contributor`) cấp cho GitHub OIDC Service Principal `vsl-github-actions-staging`.
  - `infra/budget.tf`: `azurerm_consumption_budget_subscription.monthly` `$5 USD/tháng` với cảnh báo `20%` (`$1`) và `100%` (`$5`).
- **Tài nguyên Azure đang chạy live tại `rg-vsl-staging` (`eastasia`) ngoài state Container App:**
  - Log Analytics Workspace: `workspace-rgvslstaging8EBp` (`SKU: PerGB2018`, `retentionInDays: 30`).
  - Container Apps Environment: `cae-vsl-staging-std` (`environmentMode: WorkloadProfiles`, `workloadProfiles: [{name: "Consumption", workloadProfileType: "Consumption"}]`, `appLogsConfiguration.destination: "log-analytics"`, `defaultDomain: happyforest-6510ce4b.eastasia.azurecontainerapps.io`, `zoneRedundant: false`).
  - User Assigned Identity cho runtime pull: `id-vsl-api-pull` đã được gán role `AcrPull` trên `vslacr3795`.
  - Container App: `vsl-api` (`activeRevisionsMode: Multiple`, `maxInactiveRevisions: 100`, `workloadProfileName: Consumption`, `identity: UserAssigned [id-vsl-api-pull]`, `registries: [{server: vslacr3795.azurecr.io, identity: id-vsl-api-pull}]`, `ingress: external=true, allowInsecure=false, targetPort=8080, transport=Auto, traffic=[latestRevision:true, weight:100]`, image `vslacr3795.azurecr.io/vsl-api:9a1c3aa847e19ef4a85d6bec9d36afc3d5c5e76f`, `cpu: 1.0`, `memory: 2Gi`, `env: VSL_ALLOWED_ORIGINS=https://sign-language-classification.pages.dev`, `scale: minReplicas=1, maxReplicas=2, cooldownPeriod=300, pollingInterval=30`). Chưa có `VSL_MODEL_PATH`, chưa có `startup_probe`/`readiness_probe`/`liveness_probe`.
- **Frontend hiện có (`web/`):** Trang tĩnh trên Cloudflare Pages (`https://sign-language-classification.pages.dev`), trong đó `web/config.js` đang trỏ tới `https://vsl-vietnam.azurewebsites.net` (App Service backup); không bị thay đổi bởi US-020.

- **`azurerm_log_analytics_workspace.vsl`**:
  - `name = var.log_analytics_workspace_name` (staging: `"workspace-rgvslstaging8EBp"`)
  - `resource_group_name = var.resource_group_name`
  - `location = var.location`
  - `sku = "PerGB2018"`
  - `retention_in_days = 30`
- **`azurerm_container_app_environment.vsl`**:
  - `name = var.container_app_environment_name` (staging: `"cae-vsl-staging-std"`)
  - `resource_group_name = var.resource_group_name`
  - `location = var.location`
  - `log_analytics_workspace_id = azurerm_log_analytics_workspace.vsl.id`
  - `logs_destination = "log-analytics"`
  - `internal_load_balancer_enabled = false`
  - `zone_redundancy_enabled = false`
  - `workload_profile`: `name = "Consumption"`, `workload_profile_type = "Consumption"` (giữ nguyên chế độ `WorkloadProfiles` Consumption hiện có của `cae-vsl-staging-std`, không tạo `Cloud Load Balancer`/`NAT Gateway`/`VNet` trả phí theo giờ theo `BR-016`).

### 6.2. Runtime ACR Pull Identity (`infra/container_app.tf`)

- **`azurerm_user_assigned_identity.vsl_api_pull`**:
  - `name = "id-${var.container_app_name}-pull"` (staging: `"id-vsl-api-pull"`)
  - `resource_group_name = var.resource_group_name`
  - `location = var.location`
- **`azurerm_role_assignment.vsl_api_acr_pull`**:
  - `scope = azurerm_container_registry.vsl.id`
  - `role_definition_name = "AcrPull"`
  - `principal_id = azurerm_user_assigned_identity.vsl_api_pull.principal_id`
  - `principal_type = "ServicePrincipal"`
  - `skip_service_principal_aad_check = true`

### 6.3. Azure Container App `vsl-api` (`infra/container_app.tf`)

- **`azurerm_container_app.vsl_api`**:
  - `name = var.container_app_name` (staging: `"vsl-api"`)
  - `resource_group_name = var.resource_group_name`
  - `container_app_environment_id = azurerm_container_app_environment.vsl.id`
  - `revision_mode = "Multiple"` (giữ tương thích quy trình rollback revision traffic của `scripts/rollback.py` / `US-031`)
  - `workload_profile_name = "Consumption"`
  - `max_inactive_revisions = 100`
  - `identity`: `type = "UserAssigned"`, `identity_ids = [azurerm_user_assigned_identity.vsl_api_pull.id]`
  - `registry`: `server = azurerm_container_registry.vsl.login_server`, `identity = azurerm_user_assigned_identity.vsl_api_pull.id`
  - `ingress`:
    - `external_enabled = true`
    - `allow_insecure_connections = false`
    - `target_port = 8080`
    - `transport = "auto"`
    - `traffic_weight`: `percentage = 100`, `latest_revision = true`
  - `template`:
    - `min_replicas = var.container_min_replicas` (mặc định `0`, staging bắt buộc `0` theo `BR-016` / `AC-020-01`)
    - `max_replicas = var.container_max_replicas` (mặc định `3`, ràng buộc `>= var.container_min_replicas` và `<= 3` trên staging)
    - `cooldown_period_in_seconds = var.scale_cooldown_seconds` (mặc định `300` giây = 5 phút, bảo đảm sau 15 phút nhàn rỗi sẽ scale về `0` ở `AC-020-02`)
    - `polling_interval_in_seconds = 30`
    - `termination_grace_period_seconds = var.container_termination_grace_period_seconds` (mặc định `60` giây)
    - `http_scale_rule`: `name = "http-scaling"`, `concurrent_requests = tostring(var.http_scale_concurrent_requests)` (mặc định `"10"`)
    - `container`:
      - `name = var.container_app_name`
      - `image = "${azurerm_container_registry.vsl.login_server}/${var.image_repository}:${var.image_tag}"`
      - `cpu = var.container_cpu` (mặc định `1.0`)
      - `memory = var.container_memory` (mặc định `"2Gi"`, nằm trong khoảng `1–2 GiB` của backlog và khớp cặp CPU/RAM hợp lệ của Azure Container Apps Consumption cho `1.0` vCPU; validator cho phép `"1Gi"`, `"1.5Gi"`, `"2Gi"` khi CPU tương ứng hợp lệ)
      - `env`:
        - `PORT = "8080"`
        - `VSL_MODEL_PATH = var.model_path` (mặc định `"/app/train/vsl_cnn_pose_keras.h5"`)
        - `VSL_ALLOWED_ORIGINS = var.allowed_origins` (nếu không rỗng; staging = `"https://sign-language-classification.pages.dev"`)
      - `startup_probe`: `transport = "HTTP"`, `path = "/health"`, `port = 8080`, `initial_delay = 5`, `interval_seconds = 5`, `timeout = 5`, `failure_count_threshold = 24` (dành tối đa ~125s cho cold start nạp ResNet50 `137MB` trước khi kích hoạt readiness/liveness)
      - `readiness_probe`: `transport = "HTTP"`, `path = "/health"`, `port = 8080`, `initial_delay = 0`, `interval_seconds = 10`, `timeout = 5`, `failure_count_threshold = 3`, `success_count_threshold = 1`
      - `liveness_probe`: `transport = "HTTP"`, `path = "/health"`, `port = 8080`, `initial_delay = 10`, `interval_seconds = 30`, `timeout = 5`, `failure_count_threshold = 3`
  - **Ràng buộc `lifecycle.precondition` trên `azurerm_container_app.vsl_api`:**
    1. `var.container_max_replicas >= var.container_min_replicas`
    2. `var.environment != "staging" || var.container_min_replicas == 0` (chống sai lệch `BR-016` trên staging)
    3. `var.container_cpu != 1 || var.container_memory == "2Gi"` (đúng quy tắc cặp tài nguyên Consumption của Azure Container Apps)
  - **Ghi chú về `timeout 60s` trên Azure Container Apps:** Đã kiểm chứng trực tiếp schema của `azurerm` v4.81.0: block `ingress` của `azurerm_container_app` **không có** thuộc tính `request_timeout` như Cloud Run (Azure Envoy ingress áp đặt giới hạn platform HTTP request timeout cố định 240 giây). Tham số `60s` được hiện thực đúng khả năng của nền tảng tại `termination_grace_period_seconds = 60`, kết hợp probe `timeout = 5s` và `startup_probe` cho phép quá trình nạp model hoàn tất sạch sẽ.

## 7. Business Flow

### 7.1. Luồng Import & Apply IaC Staging

```
Người vận hành kiểm tra Azure login (`az account show`) và backend `vslstate2026/tfstate`
  → `terraform -chdir=infra init` kết nối remote state `staging.tfstate`
  → `terraform -chdir=infra import` 5 resource staging hiện có vào state:
      1. azurerm_log_analytics_workspace.vsl          (workspace-rgvslstaging8EBp)
      2. azurerm_container_app_environment.vsl        (cae-vsl-staging-std)
      3. azurerm_user_assigned_identity.vsl_api_pull  (id-vsl-api-pull)
      4. azurerm_role_assignment.vsl_api_acr_pull     (role AcrPull trên vslacr3795)
      5. azurerm_container_app.vsl_api                (vsl-api)
  → `terraform -chdir=infra plan -var-file="environments/staging.tfvars"`
      - xác minh KHÔNG destroy/replace resource hiện hữu (chỉ update in-place `min_replicas: 1 -> 0`, `max_replicas: 2 -> 3`, probes `/health`, `VSL_MODEL_PATH`, HTTP scale rule)
  → Sau khi chủ dự án duyệt, chạy `terraform -chdir=infra apply`
  → Kiểm tra `terraform state show` (`min_replicas = 0`) + `GET https://<fqdn>/health` trả `200 OK`
```

### 7.2. Luồng Runtime Scale-to-Zero (`AC-020-02`)

```
Không có HTTP request tới `vsl-api` trong 300s (cooldown) và tối thiểu 15 phút quan sát
  → KEDA HTTP scaler giảm số replica từ N về `0`
  → Metering `vCPU-seconds` và `Memory GiB-seconds` giảm về `0` khi không có replica chạy
  → Khi có request tiếp theo tới `/health` hoặc `/predict`:
      ACA kích hoạt replica mới → container nạp `/app/train/vsl_cnn_pose_keras.h5`
      → `startup_probe` kiểm tra `/health` (port 8080) → khi model sẵn sàng (`200 OK`), `readiness_probe` mở traffic và phục vụ request
```

## 15. Risks
