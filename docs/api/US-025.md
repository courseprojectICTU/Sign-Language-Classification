## 1. Mục tiêu

- Thêm CORS middleware cho FastAPI, dùng allowlist cấu hình bằng `VSL_ALLOWED_ORIGINS`.
- Cho phép preflight cho các phương thức API cần thiết và từ chối origin không được cấu hình.
- Phạm vi hoàn thành trong US-025: backend CORS (`src/vsl/service.py`) và unit/contract tests (`tests/test_cors.py`). Phần giao diện web (`web/app.js`) hiển thị trạng thái loading/lỗi đã được triển khai ở US-022; cấu hình `VSL_ALLOWED_ORIGINS` trên môi trường Azure Container Apps thực tế cần đồng bộ theo US-024.

## 6. Proposed API Changes

### 6.1. CORS response policy

- **Method / Endpoint:** Không thêm hoặc đổi endpoint; áp dụng middleware cho các route hiện có.
- **Authentication / Authorization:** Không thay đổi.
- **Allowed origins:** Giá trị phân tách bằng dấu phẩy từ `VSL_ALLOWED_ORIGINS`; mỗi giá trị phải là một origin HTTP(S) đầy đủ, ví dụ `https://sign-language-classification.pages.dev`.
- **Default:** Danh sách rỗng; không cho phép cross-origin nếu operator chưa cấu hình.
- **Wildcard:** `*` bị từ chối; không dùng origin regex hoặc suffix wildcard.
- **Methods:** `GET`, `POST`, `OPTIONS`.
- **Headers:** `Content-Type`; credentials không được bật (`allow_credentials=False`).
- **Preflight:** Origin hợp lệ và method được phép nhận response CORS từ middleware.
- **Invalid configuration:** Origin có wildcard, path, query, fragment hoặc không phải HTTP(S) làm khởi tạo app báo `ValueError` thay vì tự mở rộng allowlist.
- **HTTP status / body:** Endpoint và response body hiện có không thay đổi; request CORS bị từ chối không có `Access-Control-Allow-Origin`.

### 6.2. Environment variable

```text
VSL_ALLOWED_ORIGINS=https://sign-language-classification.pages.dev
```

Có thể cấu hình nhiều origin bằng dấu phẩy. Chỉ đưa hostname đã xác minh vào deployment environment; giá trị mặc định rỗng không cấp quyền cho bất kỳ site khác origin nào.

## 7. Business Flow

```text
FastAPI khởi tạo
  -> parse VSL_ALLOWED_ORIGINS thành origin HTTP(S) chính xác
  -> reject cấu hình wildcard hoặc URI không phải origin
  -> CORSMiddleware xử lý request/preflight
  -> origin trong allowlist nhận CORS headers; origin khác không nhận
```

## 8. Security

| Mục | Giá trị |
|---|---|
| Authentication | Không thay đổi API hiện tại |
| Authorization | CORS là chính sách trình duyệt, không thay thế authentication |
| Origin | Allowlist chính xác từ environment; không wildcard/regex |
| Credentials | Tắt (`False`) |
| Methods / headers | Chỉ `GET`, `POST`, `OPTIONS` và `Content-Type` |
| Secret | CORS origin không phải secret; không ghi token/mật khẩu vào environment này |

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| Revision Azure chưa đặt `VSL_ALLOWED_ORIGINS` | Browser trên Pages bị chặn đọc response (đã ghi nhận ở `US-024`) | Đẩy image mới từ `develop` và đặt đúng origin Pages lên Container App `vsl-api` |
| Origin sai hoặc có dấu `/path` | Backend từ chối cấu hình hoặc browser không khớp | Ghi chính xác scheme + host (+ port nếu có), không path |
| CORS bị nhầm là xác thực | API public vẫn có thể được gọi ngoài browser | Không coi CORS là cơ chế bảo vệ API |

## 17. Implementation Handoff

- **Backend nhận:** Set `VSL_ALLOWED_ORIGINS` bằng origin chính xác; không dùng `*`.
- **Frontend nhận:** `web/app.js` đọc `window.VSL_CONFIG.apiBaseUrl` và hiển thị lỗi HTTP/mạng/nghiệp vụ (`US-022`).
- **Tester nhận:** Unit/contract tests bằng `TestClient` và Playwright stub đã pass; kiểm thử E2E thật trên Pages chờ cấu hình biến env lên Azure.
- **Trạng thái nghiệm thu:** Backend CORS hoàn tất trên `develop` (PR `#28`); kiểm thử E2E với production Azure đang chờ đồng bộ revision (`US-024`).
