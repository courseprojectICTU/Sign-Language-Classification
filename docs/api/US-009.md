## 1. Mục tiêu

- Vấn đề cần giải quyết: hiện tại `POST /predict` đọc toàn bộ payload vào RAM bằng
  `await file.read()` rồi mới gọi `cv2.imdecode()`, chưa kiểm tra `Content-Type`, chưa kiểm
  tra chữ ký byte của tệp ảnh, chưa giới hạn kích thước tối đa `5 MB` và chưa ghi log
  tập trung các trường hợp bị từ chối.
- Kết quả mong đợi sau US này: mọi request tới `POST /predict` sai định dạng (kể cả tệp
  giả mạo đuôi `.jpg`/`.png` như PDF đổi tên thành `.jpg`) bị từ chối bằng **HTTP `415`**,
  ảnh vượt quá **`5 MB`** (`5 * 1024 * 1024` bytes) bị ngắt đọc sớm và từ chối bằng
  **HTTP `413`**, tệp đúng định dạng nhưng hỏng/rỗng không giải mã được trả **HTTP `400`**,
  và mọi trường hợp bị từ chối đều được ghi log `WARNING` an toàn (không chứa byte ảnh).
- Phạm vi: validation đầu vào tại `POST /predict` trong `src/vsl/service.py`, cập nhật
  bài test `400` cũ trong `tests/test_predict.py` cho khớp `BR-010` và bổ sung test
  `tests/test_us009_input_validation.py`.
- Ngoài phạm vi: thay đổi pipeline MediaPipe/heatmap/ResNet50, thay đổi schema response
  `ok`/`no_hand`/`no_face`, thêm rate limiting/auth, hoặc chỉnh sửa frontend `web/`.

- Backend hiện có: FastAPI tại `src/vsl/service.py` chạy trong container `2.0 GiB RAM`

  - Bài test cũ `tests/test_predict.py::test_predict_file_khong_phai_anh_tra_400` đang gửi

## 6. Proposed API Changes

### 6.1. `POST /predict` — Validation đầu vào (`US-009`, `BR-010`)

- **Method:** `POST`
- **Endpoint:** `/predict`
- **Purpose:** Tiếp nhận ảnh hợp lệ (`JPEG`/`JPG`/`PNG`, `<= 5 MB`) trước khi giải mã ảnh và chạy MediaPipe/model.
- **Authentication / Authorization:** Public (giữ nguyên như `US-006`).
- **Query Parameters:** Giữ nguyên `top_k` (`1..23`, mặc định `3`) và `flip` (`bool`, mặc định `false`).
- **Request Body:** `multipart/form-data` với trường `file` (`UploadFile`).
- **Validation Rules:**
  1. **Model Readiness (`BR-011`):** kiểm tra `app.state.model is not None` trước tiên (giữ nguyên `503`).
  2. **Content-Type Allowlist:** lấy phần media type trước dấu `;`, chuẩn hóa chữ thường; phải thuộc `{"image/jpeg", "image/jpg", "image/png"}`.
  3. **Magic-Bytes Signature (chống giả mạo định dạng như PDF đổi tên `.jpg`):**
     - Với `image/jpeg` hoặc `image/jpg`: nếu payload khác rỗng thì byte đầu phải khớp chữ ký JPEG (`\xff\xd8\xff`, hoặc tiền tố `\xff\xd8` nếu tệp bị cắt ngắn dưới 3 byte để phân loại là dữ liệu ảnh hỏng `400`).
     - Với `image/png`: nếu payload khác rỗng thì byte đầu phải khớp chữ ký PNG (`\x89PNG\r\n\x1a\n`, hoặc tiền tố của chữ ký này nếu bị cắt ngắn dưới 8 byte để phân loại là dữ liệu ảnh hỏng `400`).
     - Nếu không khớp (ví dụ `%PDF-`, HTML, plain text, GIF, WebP, hoặc gửi PNG dưới `image/jpeg` hay ngược lại) → trả **`415 Unsupported Media Type`**.
  4. **Size Boundary (`5 MB` = `5 * 1024 * 1024` = `5.242.880` bytes):**
     - Đọc từng chunk `64 KiB` (`65.536` bytes); dừng đọc ngay khi tổng số byte vượt `5.242.880` (không đọc quá `5 MB + 1 chunk` vào bộ nhớ).
     - Kiểm tra chữ ký byte ngay trên chunk đầu tiên để tệp giả mạo định dạng bị từ chối `415` sớm.
     - Vượt quá `5 MB` → trả **`413 Payload Too Large`** kèm thông báo rõ giới hạn `5 MB`.
     - Đúng `5 MB` (`<= 5.242.880` bytes) → hợp lệ.
  5. **Image Decode Integrity:**
     - Nếu dữ liệu rỗng (`0` byte) hoặc giải mã OpenCV (`cv2.imdecode`) trả `None` / ném `ValueError` → trả **`400 Bad Request`**.

#### Phản hồi lỗi mới / được chuẩn hóa

- **HTTP `415 Unsupported Media Type`** (sai `Content-Type` hoặc chữ ký tệp không khớp JPEG/JPG/PNG):
  ```json
  {
    "detail": "Định dạng tệp không được hỗ trợ. Chỉ chấp nhận ảnh JPEG/JPG hoặc PNG."
  }
  ```
- **HTTP `413 Payload Too Large`** (vượt quá `5 MB`):
  ```json
  {
    "detail": "Kích thước tệp vượt quá giới hạn tối đa 5 MB."
  }
  ```
- **HTTP `400 Bad Request`** (tệp đúng định dạng nhưng rỗng hoặc dữ liệu ảnh bị hỏng không giải mã được):
  ```json
  {
    "detail": "Không thể giải mã dữ liệu ảnh tải lên. Vui lòng gửi tệp ảnh hợp lệ."
  }
  ```
- **HTTP `200 OK` và `503 Service Unavailable`:** Giữ nguyên 100% hợp đồng của `US-005`, `US-006`, `US-007`.

## 7. Business Flow

```text
POST /predict (multipart/form-data: file)
  │
  ├─ Kiểm tra app.state.model is None (BR-011)
  │    └─ True ──> HTTP 503 Service Unavailable
  │
  ├─ Kiểm tra media type của file.content_type (chấp nhận image/jpeg, image/jpg, image/png)
  │    └─ Không hợp lệ ──> log WARNING (reason=unsupported_content_type) ──> HTTP 415
  │
  ├─ Đọc stream theo từng chunk (64 KiB):
  │    ├─ Chunk đầu khác rỗng nhưng không khớp chữ ký JPEG/PNG của media type
  │    │    ──> log WARNING (reason=invalid_file_signature) ──> HTTP 415
  │    └─ Tổng byte > 5 * 1024 * 1024 (5 MB)
  │         ──> dừng đọc, log WARNING (reason=payload_too_large) ──> HTTP 413
  │
  ├─ Nếu len(content) == 0
  │    └─ log WARNING (reason=empty_file) ──> HTTP 400
  │
  ├─ Gọi extract_landmarks_from_image(content, flip=flip)
  │    └─ Ném ValueError (ảnh JPEG/PNG hỏng) ──> log WARNING (reason=corrupt_image_data) ──> HTTP 400
  │
  └─ Tiếp tục luồng MediaPipe -> create_heatmap -> ResNet50 (US-006 / US-007) ──> HTTP 200
```

## 8. Security

| Mục | Giá trị |
|---|---|
| Authentication | Public (giữ nguyên như `US-006`) |
| Authorization | Tất cả vai trò (`A01`, `A02`, `A03`) |
| Dữ liệu nhạy cảm | Không lưu ảnh xuống đĩa; không đưa byte ảnh hoặc chuỗi thô từ payload vào log |
| Giới hạn tài nguyên | Đọc chunk + ngắt sớm ở `5 MB` (`5.242.880` bytes) tránh cạn RAM (`OOM`) khi nhận tệp 20 MB+ |
| Kiểm soát giả mạo loại tệp | Kiểm tra kép cả `Content-Type` và magic bytes JPEG/PNG để chặn tệp không phải ảnh đổi đuôi `.jpg`/`.png` |
| Không đưa vào request | `N/A` — endpoint chỉ nhận file ảnh và query `top_k`, `flip` |

## 14. Test Scenarios

| Loại | Mô tả | Dữ liệu |
|---|---|---|

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| Tệp có dung lượng cực lớn (ví dụ 20 MB–500 MB) gửi qua multipart | Có thể chiếm nhiều RAM nếu dùng `await file.read()` một lần | Đọc theo chunk `64 KiB` và dừng ngay khi `total_bytes > 5 * 1024 * 1024` |

| Test cũ `test_predict_file_khong_phai_anh_tra_400` gửi `application/octet-stream` | Thất bại vì `BR-010` trả `415` cho MIME ngoài allowlist | Cập nhật test cũ đó dùng `image/jpeg` + JPEG hỏng cho case `400`, bổ sung test `415` cho `application/octet-stream` |
