# API Design — US-028 Pipeline Frontend Với Trigger Theo Đường Dẫn Và Preview Deployment

> **Trạng thái:** `ANALYSIS_READY`  
> **Epic:** `EPC-07` · **Nhánh:** `feature/US-028` · **Ngày lập:** `2026-11-17`  
> **Người soạn:** `P2 - Frontend & P4 - CI/CD` · **Người duyệt:** `Chủ dự án (đã duyệt Cổng A)`  
>
> File này là **hợp đồng kỹ thuật luồng CI/CD frontend** và cơ chế triển khai bản xem trước (Preview Deployment) trên Cloudflare Pages.
> US-028 **không** tạo hoặc thay đổi endpoint HTTP backend Python trong `src/vsl/service.py`.

---

## 1. Mục tiêu

- **Vấn đề cần giải quyết:** 
  1. Hiện tại Cloudflare Pages đang kết nối Git Integration toàn bộ repository (`*`), dẫn đến việc mọi commit/push (kể cả chỉ sửa backend, infra hoặc tài liệu) đều kích hoạt build frontend, gây lãng phí quota 500 build/tháng và tốn thời gian.
  2. Người đánh giá Pull Request chưa có cơ chế tự động nhận URL xem trước (Preview Deployment) được bình luận ngay trên PR để dùng thử giao diện thực tế trước khi duyệt merge.
- **Kết quả mong đợi sau US-028:**
  1. Thiết lập workflow GitHub Actions `.github/workflows/frontend.yml` với bộ lọc đường dẫn nghiêm ngặt: chỉ kích hoạt khi có thay đổi trong `web/**` (hoặc chính workflow `frontend.yml`).
  2. Khi có `pull_request` vào `develop` hoặc `main`: tự động chạy `wrangler pages deploy web` với tham số `--branch=${{ github.head_ref }}`, trích xuất URL preview và tạo/cập nhật comment chứa URL xem trước vào Pull Request (`AC-028-01`).
  3. Khi Pull Request chỉ chỉnh sửa backend, hạ tầng hoặc tài liệu: workflow frontend hoàn toàn không chạy (`AC-028-02`).
  4. Phân định rõ 2 môi trường theo quyết định tại Cổng A:
     - Push/merge vào `develop` → Triển khai môi trường **Staging** (`--branch=develop`).
     - Push/merge vào `main` → Triển khai môi trường **Production** (`--branch=main`).
- **Phạm vi:** 
  - Khai báo workflow `.github/workflows/frontend.yml`.
  - Bộ kiểm thử hợp đồng workflow `tests/test_frontend_workflow.py`.
  - Quản lý xác thực qua 2 secret: `CLOUDFLARE_API_TOKEN` (quyền tối thiểu `Pages:Edit` theo `BR-020`) và `CLOUDFLARE_ACCOUNT_ID`.
  - Cập nhật tài liệu vận hành và bảng trạng thái hệ thống.
- **Ngoài phạm vi:**
  - Không sửa đổi mã nguồn ứng dụng frontend tĩnh trong `web/` (`index.html`, `app.js`, `styles.css`, `config.js`, `labels.json`).
  - Không sửa đổi endpoint hay backend CORS trong `src/vsl/service.py`. *(Lưu ý: URL preview động có định dạng `https://<branch>.sign-language-classification.pages.dev` sẽ kiểm tra toàn diện phần giao diện, camera, preview và validation; việc gọi API sang Azure sẽ yêu cầu bổ sung origin vào `VSL_ALLOWED_ORIGINS` nếu muốn kiểm thử live xuyên domain).*
  - Không tự ý đồng bộ mã từ `develop` sang `main` (`US-027`).

## 6. Proposed Workflow Contract (`.github/workflows/frontend.yml`)

### 6.1. Điều kiện kích hoạt (Triggers)

- **Sự kiện `pull_request`:**
  - Nhánh đích (`branches`): `develop`, `main`.
  - Bộ lọc đường dẫn (`paths`):
    - `web/**`
    - `.github/workflows/frontend.yml`
- **Sự kiện `push`:**
  - Nhánh kích hoạt (`branches`): `develop`, `main`.
  - Bộ lọc đường dẫn (`paths`):
    - `web/**`

### 6.2. Kiểm soát đồng thời (Concurrency)

```yaml
concurrency:
  group: pages-${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

### 6.3. Phân quyền (Permissions)

```yaml
permissions:
  contents: read
  pull-requests: write
  deployments: write
```

### 6.4. Các công việc thực thi (Jobs & Steps)

1. **Job `deploy-pages`:**
   - Môi trường chạy: `ubuntu-latest`.
   - Timeout: `15 minutes`.
   - **Bước 1 — Checkout:** Dùng `actions/checkout@v4` (không cần LFS vì chỉ lấy tài nguyên tĩnh trong `web/`).
   - **Bước 2 — Xác thực cấu hình Secret:** Kiểm tra sự tồn tại của `CLOUDFLARE_API_TOKEN` và `CLOUDFLARE_ACCOUNT_ID`. Nếu thiếu, thông báo lỗi rõ ràng.
   - **Bước 3 — Xác định tên nhánh triển khai (`branch_name`):**
     - Khi `pull_request`: lấy tên nhánh nguồn `${{ github.head_ref }}` để Cloudflare Pages gán nhãn Preview deployment.
     - Khi `push` vào `develop`: đặt nhánh là `develop` (môi trường Staging).
     - Khi `push` vào `main`: đặt nhánh là `main` (môi trường Production).
   - **Bước 4 — Triển khai bằng `cloudflare/wrangler-action@v3`:**
     - `apiToken`: `${{ secrets.CLOUDFLARE_API_TOKEN }}`
     - `accountId`: `${{ secrets.CLOUDFLARE_ACCOUNT_ID }}`
     - `command`: `pages deploy web --project-name=sign-language-classification --branch=${{ env.DEPLOY_BRANCH }}`
     - `gitHubToken`: `${{ secrets.GITHUB_TOKEN }}`
   - **Bước 5 — Comment URL vào PR (Chỉ chạy khi `pull_request`):**
     - Dùng `actions/github-script@v7`.
     - Tìm kiếm comment cũ chứa marker `<!-- vsl-cloudflare-pages-preview -->`.
     - Nếu đã có: Cập nhật (update) nội dung comment với commit SHA và deployment URL mới nhất.
     - Nếu chưa có: Tạo mới (create) comment chứa bảng tổng hợp: Preview URL, Commit-specific Deployment URL và Git SHA.

## 7. Business Flow

```
Lập trình viên mở PR hoặc đẩy commit sửa web/**
  │
  ├─ PR chứa thay đổi ngoài web/** (ví dụ: src/vsl/..., infra/..., docs/...)
  │    └── Pipeline frontend.yml KHÔNG kích hoạt (AC-028-02 - PASS)
  │
  └─ PR hoặc commit có thay đổi trong web/**
       │
       ├─ [pull_request]:
       │    ├── Chạy wrangler pages deploy web --branch=<head_ref>
       │    ├── Cloudflare Pages sinh URL: https://<hash>.sign-language-classification.pages.dev
       │    │   và alias URL: https://<branch>.sign-language-classification.pages.dev
       │    └── GitHub Actions comment / cập nhật Preview URL lên PR (AC-028-01 - PASS)
       │
       ├─ [push develop]:
       │    └── Chạy wrangler pages deploy web --branch=develop (Triển khai Staging)
       │
       └─ [push main]:
            └── Chạy wrangler pages deploy web --branch=main (Triển khai Production)
```

|---|---|

## 15. Risks & Mitigation

| Rủi ro | Mức độ | Biện pháp giảm thiểu |
|---|---|---|
| Lỗi CORS khi gọi backend từ Preview URL | Trung bình | Ghi nhận rõ trong tài liệu: Preview URL phục vụ kiểm tra toàn diện UI/UX/Camera/Preview; nếu cần gọi backend Azure thật, cần bổ sung origin vào `VSL_ALLOWED_ORIGINS` theo `BR-018`. |
| Xung đột deploy kép với Git Integration | Thấp | Hướng dẫn chủ dự án tắt `Automatic deployments` trên Cloudflare Dashboard trước khi hợp nhất workflow. |
| Lỗi phân quyền khi comment lên PR từ fork | Thấp | Workflow yêu cầu `pull-requests: write`. Với các nhánh trong cùng repo (`courseprojectICTU`), quyền này luôn khả dụng. |
| Thiếu hoặc sai Secret trong GitHub | Thấp | Thêm bước kiểm tra tiền điều kiện (validation step) ngay đầu job; nếu thiếu secret sẽ dừng sớm và thông báo rõ ràng thay vì fail ngầm. |
