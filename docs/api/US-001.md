## 1. Mục tiêu

- **Vấn đề:** công thức sinh heatmap đang tồn tại **3 bản sao**. Nếu sửa một bản mà quên

- **Phạm vi:** trích xuất + xoá 3 bản trùng. **Không** đổi công thức, không đổi tham số
  mặc định, không tối ưu tốc độ.
- **Ngoài phạm vi:** tách `VIETNAMESE_ALPHABET` (US-002), bỏ đường dẫn tuyệt đối (US-003),
  đóng gói API HTTP (EPC-02).

## 4. Existing APIs

Hàm `create_heatmap` hiện tồn tại ở 3 nơi. Chữ ký giống nhau, **khác nhau ở kiểm tra đầu vào**:

| # | Vị trí | Dòng | Chữ ký | Có `len % 3` check? | Hash thân hàm |
|---|---|---|---|---|---|
| 1 | `train/train_cnn_pose_keras.ipynb` (cell 3) | ~55 | `create_heatmap(landmarks, img_size=(224,224), sigma=5)` | ✅ **Có** (trả zeros + print) | `23fa6c7b47e8` |
| 2 | `run_realtime.ipynb` (cell 5) | ~79 | giống | ❌ Không | `f89309f01e1e` |
| 3 | `run_realtime.py` | 33 | giống | ❌ Không | `f89309f01e1e` |

**Bản 2 và 3 giống hệt nhau từng byte.** Bản 1 là bản 2/3 **cộng thêm** guard 3 dòng:

```python
if len(landmarks) % 3 != 0:
    print(f"Warning: Invalid landmark data length {len(landmarks)}. Expected multiple of 3.")
    return np.zeros((img_size[0], img_size[1], 3), dtype=np.uint8)
```

→ Với đầu vào **hợp lệ** (93 phần tử), cả 3 bản cho kết quả **giống nhau**. Guard chỉ
ảnh hưởng đầu vào sai. Hợp đồng chung nên lấy bản 1 (bao trùm hành vi).

## 6. Proposed API Changes

### 6.1. `create_heatmap` — hàm công khai duy nhất

- **Method:** hàm Python thuần (không HTTP)
- **Endpoint / đường dẫn:** `src/vsl/heatmap.py`
- **Purpose:** sinh heatmap 224×224×3 từ vector landmark
- **Authentication / Authorization:** không áp dụng (thư viện nội bộ)
- **Signature:**

```python
def create_heatmap(landmarks, img_size=(224, 224), sigma=5) -> np.ndarray:
```

- **Path Parameters:** không
- **Query Parameters:** không
- **Request Body:** không

**Tham số:**

| Tên | Kiểu | Mặc định | Ràng buộc |
|---|---|---|---|
| `landmarks` | `Sequence[float]` | — | **bắt buộc**; độ dài chia hết cho 3; thực tế 93 phần tử (x,y,z xen kẽ, hand trước face sau — BR-001) |
| `img_size` | `tuple[int,int]` | `(224, 224)` | > 0 |
| `sigma` | `float` | `5` | > 0 |

**Response (giá trị trả về):**

| Mục | Giá trị |
|---|---|
| Kiểu | `numpy.ndarray` |
| Shape | `(img_size[0], img_size[1], 3)` = `(224,224,3)` |
| dtype | **`uint8`** |
| Khoảng giá trị | `0..255` |
| Kênh | 3 kênh **giống hệt nhau** (`np.stack([h]*3, axis=2)`) |
| Trường hợp không có landmark hợp lệ | mảng **zeros** cùng shape/dtype (sau guard hoặc khi `max == 0`) |

**HTTP Status / Error Cases:** không áp dụng — không có HTTP.

**Validation (theo BR-002, giữ nguyên hành vi cũ):**

| Điều kiện | Hành vi |
|---|---|
| `len(landmarks) % 3 != 0` | `print(...)` cảnh báo + trả `np.zeros((H,W,3), uint8)` — **không raise** |
| Toạ độ `(0, 0)` | bỏ qua điểm đó (coi là landmark thiếu) |
| `x*W` hoặc `y*H` ngoài biên | bỏ qua điểm đó |
| `max(heatmap) == 0` | không chia; trả zeros |

## 7. Business Flow

```
landmarks (93 giá trị)
  → guard: len % 3 != 0 ? → zeros + warning
  → khởi tạo heatmap float32 (H,W)
  → với mỗi bộ (x,y,z): bỏ qua nếu (x==0 and y==0)
      → (x_px, y_px) = (int(x*W), int(y*H)); bỏ qua nếu ngoài biên
      → cộng dồn Gaussian exp(-(j²+k²)/(2σ²)) với j,k ∈ [-15..15]
  → nếu max > 0: chia cho max
  → nhân 255, ép uint8
  → np.stack 3 kênh → (H,W,3) uint8
```

Lưu ý **bất biến**: trục `z` **không được dùng**; phép nhân dùng `x*img_size[1]` và
`y*img_size[0]` (đúng như code cũ — giữ nguyên, không "sửa").
