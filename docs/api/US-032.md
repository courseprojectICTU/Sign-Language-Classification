# Operations / Runbook Design — US-032 Rollback frontend về deployment trước

> **Trạng thái:** `ANALYSIS_READY` — tài liệu thiết kế quy trình hoàn tác frontend hoàn tất
> **Epic:** `EPC-08` · **Nhánh:** `feature/US-032` · **Ngày:** 2026-11-21
> **Người soạn:** Antigravity · **Người duyệt:** Chủ dự án
> **Business Rule:** `BR-022` (Rehearsed Rollback)
>
> Frontend tĩnh của hệ thống được lưu trữ và phục vụ trên **Cloudflare Pages** (dự án `sign-language-classification`).
> Không cần kích hoạt build lại khi hoàn tác; quy trình rollback tận dụng kiến trúc immutable deployment
> của Cloudflare Pages để chuyển traffic tức thời sang bản build ổn định trước đó.

---

## 1. Mục tiêu

- **Vấn đề cần giải quyết:** Khi một bản triển khai frontend mới gặp lỗi giao diện, lỗi định tuyến hoặc lỗi JavaScript phía máy khách, nhóm vận hành cần khôi phục lại phiên bản frontend ổn định trước đó ngay lập tức mà không phải chờ đợi quy trình build và deploy lại mã nguồn.
- **Kết quả mong đợi sau US-032:**
  - Quy trình hoàn tác frontend được tài liệu hóa chi tiết, chuẩn xác trong `docs/RUNBOOK.md` (Mục 5.3).
  - Có hướng dẫn từng bước qua cả hai phương thức: **Cloudflare Pages Dashboard** (giao diện đồ họa) và **Cloudflare API / Wrangler CLI** (dòng lệnh).
  - Xác định rõ phương pháp nhận diện Deployment ID ổn định gần nhất.
  - Tuân thủ quy tắc nghiệp vụ `BR-022`: Hoàn tất diễn tập thực tế (Rehearsal) với thời gian chuyển đổi dưới 10 giây.
- **Phạm vi:** Hoàn tác frontend tĩnh trên Cloudflare Pages (`sign-language-classification.pages.dev`).
- **Ngoài phạm vi:** Hoàn tác backend Azure Container Apps (thuộc phạm vi `US-031` / `scripts/rollback.py`), thay đổi mã nguồn logic ứng dụng.

## 3. Existing Architecture

- Frontend tĩnh gồm các tệp mã nguồn HTML/JS/CSS tại thư mục `web/` (`index.html`, `app.js`, `styles.css`, `config.js`, `labels.json`).
- Triển khai trên nền tảng **Cloudflare Pages** với tên dự án: `sign-language-classification`.
- Tên miền chính thức (Production): `https://sign-language-classification.pages.dev`.
- Tên miền nhánh phát triển (Staging): `https://develop.sign-language-classification.pages.dev`.
- Mỗi lần kích hoạt workflow `.github/workflows/frontend.yml`, Cloudflare Pages tạo một immutable deployment có mã định danh duy nhất (Deployment ID dạng UUID).
- Cloudflare Pages lưu trữ toàn bộ lịch sử các bản deployment trong quá khứ và hỗ trợ tính năng **Instant Rollback** (trỏ tên miền chính về deployment cũ mà không cần build lại).

## 6. Proposed Operations Changes

### 6.1. Phương thức 1: Hoàn tác qua Cloudflare Pages Dashboard (Khuyến nghị vận hành)

1. **Bước 1:** Đăng nhập vào [Cloudflare Dashboard](https://dash.cloudflare.com/) bằng tài khoản quản trị.
2. **Bước 2:** Điều hướng tới **Compute (Workers & Pages)** 👉 Chọn dự án **`sign-language-classification`**.
3. **Bước 3:** Chuyển sang thẻ **Deployments**. Danh sách toàn bộ các lần triển khai trong lịch sử sẽ hiển thị kèm theo Commit SHA, ngày giờ và nhánh tương ứng.
4. **Bước 4:** Xác định bản deployment ổn định liền trước bản đang gặp lỗi (nhận diện qua commit SHA thành công trước đó trên nhánh `main`).
5. **Bước 5:** Bấm vào biểu tượng menu ba chấm `...` bên cạnh bản deployment đó 👉 Chọn **Rollback to this deployment**.
6. **Bước 6:** Xác nhận trên hộp thoại cảnh báo. Cloudflare Pages sẽ chuyển 100% lưu lượng của domain `sign-language-classification.pages.dev` về bản build này ngay lập tức (dưới 10 giây).

### 6.2. Phương thức 2: Hoàn tác bằng Cloudflare Pages CLI / API

Khi cần hoàn tác qua script dòng lệnh hoặc tự động hóa CI:
```bash
# Liệt kê các deployments gần nhất
npx wrangler pages deployment list --project-name=sign-language-classification

# Triển khai lại hoặc gán bí danh cho deployment cụ thể (hoặc gọi Cloudflare REST API)
curl -X POST "https://api.cloudflare.com/client/v4/accounts/${CLOUDFLARE_ACCOUNT_ID}/pages/projects/sign-language-classification/deployments/${TARGET_DEPLOYMENT_ID}/rollback" \
     -H "Authorization: Bearer ${CLOUDFLARE_API_TOKEN}"
```

## 7. Business Flow

```text
Phát hiện sự cố Frontend (Lỗi JS / Vỡ layout / Sai endpoint)
  │
  ├── 1. Xác định Deployment ID ổn định gần nhất trên tab Deployments
  │
  ├── 2. Chọn "Rollback to this deployment" trên Cloudflare Pages
  │
  ├── 3. Cloudflare Pages cập nhật con trỏ Production Domain (< 10 giây)
  │
  ├── 4. Kiểm tra trực tiếp bằng trình duyệt (Ctrl+Shift+R / Incognito)
  │      Xác nhận config.js và giao diện web đã quay về trạng thái ổn định
  │
  └── 5. Ghi nhận nhật ký diễn tập / sự cố vào Runbook theo BR-022
```

## 15. Risks

| Rủi ro | Ảnh hưởng | Biện pháp giảm thiểu |
|---|---|---|
| Operator rollback nhầm về bản build quá cũ | Giao diện bị thiếu tính năng hoặc kết nối sai backend cũ | Runbook hướng dẫn đối chiếu Commit SHA trước khi bấm xác nhận |
