## 1. Mục tiêu

- **Vấn đề cần giải quyết:**
  Trước US-006, mô hình AI chỉ có thể chạy offline qua script OpenCV nội bộ (`run_realtime.py`) hoặc Jupyter Notebook (`run_realtime.ipynb`). Để người dùng cuối có thể sử dụng ứng dụng nhận diện ngôn ngữ ký hiệu tiếng Việt qua trình duyệt web mà không cần cài đặt môi trường Python hay tải model nặng 137 MB về máy, hệ thống cần một API HTTP công khai nhận tệp ảnh và trả về kết quả dự đoán.
  Đặc biệt, để triệt tiêu hoàn toàn rủi ro sai lệch toạ độ (Risk R-1 khi chạy MediaPipe JavaScript trên trình duyệt), toàn bộ pipeline trích xuất landmark bằng MediaPipe Python sẽ được thực thi đồng nhất phía server backend.
- **Kết quả mong đợi sau US này:**
  1. Cung cấp endpoint công khai `POST /predict` nhận tệp ảnh tải lên (Multipart Form Data).
  2. Triển khai pipeline suy luận hoàn chỉnh trên server:
     - Đọc và giải mã dữ liệu ảnh từ buffer bộ nhớ (OpenCV / Pillow).
     - Lật ngang ảnh (`cv2.flip(image, 1)`) để đảm bảo cùng hệ quy chiếu gương với dữ liệu huấn luyện ([BR-007](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)).
     - Trích xuất landmark qua `MediaPipe Hands` (tối đa 1 tay) và `MediaPipe FaceMesh` (10 điểm mặt cố định).
     - Xây dựng vector 93 toạ độ đúng thứ tự: 63 toạ độ tay trước, 30 toạ độ mặt sau ([BR-001](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)).
     - Sinh heatmap 224x224x3 bằng hàm duy nhất `create_heatmap` ([BR-002](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)).
     - Tiền xử lý theo kiểu Caffe bằng `preprocess_input` của ResNet50 (trừ mean BGR, không chia 255) ([BR-006](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)).
     - Chạy mô hình ResNet50 đã nạp sẵn trong `app.state.model` ([BR-011](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)) và trả về kết quả dự đoán.
  3. Định dạng JSON kết quả phản hồi gồm: `letter` (ký tự dự đoán từ `VIETNAMESE_ALPHABET` - [BR-003](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx)), `confidence` (xác suất cao nhất), `top_k` (danh sách các ký tự có xác suất cao nhất) và `model_version`.
  4. Xử lý phản hồi thân thiện và chính xác khi trong ảnh không nhận diện đủ bàn tay hoặc khuôn mặt.
- **Phạm vi:**
  - Endpoint `POST /predict` tại `src/vsl/service.py` (hoặc module hóa trích xuất tại `src/vsl/inference.py`).
  - Kiểm thử tự động `tests/test_predict.py` kiểm chứng `AC-006-01`, `AC-006-02`, [BR-001](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx), [BR-006](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx), [BR-007](file:///D:/file/project/Sign-Language-Classification-v1.0/docs/product-backlog-cicd-2-tuan.xlsx).
- **Ngoài phạm vi:**
  - Chưa xử lý kiểm tra định dạng mime type nghiêm ngặt và giới hạn dung lượng 5 MB (thuộc `US-009`).
  - Chưa đóng gói Docker container (thuộc `US-010`).
  - Chưa xây dựng trang giao diện web HTML/JS (thuộc `US-022`).
  - Chưa mở rộng cấu hình CORS (thuộc `US-025`).

## 6. Proposed API Changes

### 6.1. `POST /predict`

- **Method:** `POST`
- **Endpoint:** `/predict`
- **Purpose:** Tiếp nhận tệp ảnh tải lên, thực hiện trích xuất landmark MediaPipe server-side, tạo heatmap, suy luận qua ResNet50 và trả về ký tự dự đoán cùng độ tin cậy.
- **Authentication:** Public (không yêu cầu token ở phiên bản v1).
- **Authorization:** `A01` (Người dùng cuối), `A02` (Lập trình viên / Frontend).
- **Request Format:** `multipart/form-data`
  - Trường form: `file` (UploadFile — nhị phân của tệp ảnh).
- **Path Parameters:** Không.
- **Query Parameters:**
  - `top_k` (int, tuỳ chọn, mặc định: `3`, phạm vi hợp lệ: `1..23`): Số lượng dự đoán có xác suất cao nhất cần trả về.
  - `flip` (bool, tuỳ chọn, mặc định: `false`): Lật gương ảnh theo chiều ngang (BR-007). Đặt `true` khi gửi ảnh webcam/selfie chụp chế độ gương; đặt `false` khi gửi ảnh chụp camera thông thường không lật.


#### Trường hợp 1: Dự đoán thành công (Có đủ tay và mặt trong ảnh) — HTTP 200 OK
- **HTTP Status:** `200 OK`
- **Content-Type:** `application/json`
- **Response Schema:**
  ```json
  {
    "detected": true,
    "letter": "a",
    "confidence": 0.9854,
    "top_k": [
      {"letter": "a", "confidence": 0.9854},
      {"letter": "c", "confidence": 0.0082},
      {"letter": "d", "confidence": 0.0031}
    ],
    "has_hand": true,
    "has_face": true,
    "model_version": "v1.0"
  }
  ```

#### Trường hợp 2: Không nhận diện đủ bàn tay hoặc khuôn mặt — HTTP 200 OK
*Giải thích thiết kế:* Khi webcam hoặc ảnh chụp của người dùng tạm thời không thấy bàn tay (hoặc không thấy khuôn mặt), đây không phải là lỗi giao thức (không phải 4xx/5xx) mà là trạng thái nghiệp vụ bình thường của khung hình nhận diện. Việc trả HTTP 200 với cờ `detected: false` kèm `has_hand` và `has_face` giúp frontend hiển thị hướng dẫn người dùng "Vui lòng đưa bàn tay vào khung hình" một cách mượt mà mà không kích hoạt thông báo lỗi network.
- **HTTP Status:** `200 OK`
- **Content-Type:** `application/json`
- **Response Schema:**
  ```json
  {
    "detected": false,
    "letter": null,
    "confidence": 0.0,
    "top_k": [],
    "has_hand": false,
    "has_face": true,
    "message": "Không nhận diện đủ 1 bàn tay và khuôn mặt trong ảnh.",
    "model_version": "v1.0"
  }
  ```

#### Trường hợp 3: Tệp ảnh không thể đọc / giải mã được — HTTP 400 Bad Request
- **HTTP Status:** `400 Bad Request`
- **Response Schema:**
  ```json
  {
    "detail": "Không thể giải mã dữ liệu ảnh tải lên. Vui lòng gửi tệp ảnh hợp lệ."
  }
  ```

#### Trường hợp 4: Mô hình chưa sẵn sàng — HTTP 503 Service Unavailable
- **HTTP Status:** `503 Service Unavailable`
- **Response Schema:**
  ```json
  {
    "detail": "Mô hình nhận diện chưa sẵn sàng. Vui lòng kiểm tra lại sau."
  }
  ```

## 7. Business Flow

```text
[Client / Frontend]
       │
       │  POST /predict (multipart/form-data: file)
       ▼
[FastAPI /predict Route]
       │
       ├─ Kiểm tra mô hình trong app.state.model (BR-011)
       │    └─ Nếu None ──> Trả HTTP 503 Service Unavailable
       │
       ├─ Đọc bytes từ `file` và giải mã qua OpenCV (cv2.imdecode)
       │    └─ Nếu lỗi decode ──> Trả HTTP 400 Bad Request
       │
       ├─ Lật gương ảnh: cv2.flip(image, 1) (BR-007)
       │
       ├─ Chuyển không gian màu: cv2.cvtColor(image, cv2.COLOR_BGR2RGB)
       │
       ├─ Chạy MediaPipe:
       │    ├─ mp_hands.process(image_rgb) ──> trích xuất 21 landmark bàn tay (x,y,z)
       │    └─ mp_face_mesh.process(image_rgb) ──> trích xuất 10 điểm mặt cố định (x,y,z)
       │
       ├─ Kiểm tra điều kiện đủ:
       │    └─ Nếu len(all_landmarks) != 93 (thiếu tay hoặc thiếu mặt):
       │         └─ Trả HTTP 200 { "detected": false, "letter": null, ... }
       │
       ├─ Dựng vector 93 toạ độ: hand_landmarks + face_landmarks (BR-001)
       │
       ├─ Sinh Heatmap: create_heatmap(all_landmarks) ──> mảng uint8 (224, 224, 3) (BR-002)
       │
       ├─ Mở rộng chiều batch: np.expand_dims(heatmap, axis=0)
       │
       ├─ Tiền xử lý ResNet50 kiểu Caffe: preprocess_input(...) (BR-006)
       │
       ├─ Suy luận mô hình: predictions = app.state.model(heatmap_input, training=False).numpy()
       │
       ├─ Ánh xạ lớp cao nhất qua VIETNAMESE_ALPHABET (BR-003)
       │
       ├─ Trích xuất top-k kết quả có xác suất lớn nhất
       │
       ▼
[Trả JSON Response HTTP 200]
```

## 8. Security

| Mục | Quy định |
|---|---|
| **Authentication** | Public (cho phép giao diện web demo trực tiếp gọi mà không cần đăng nhập). |
| **Authorization** | Tất cả vai trò (`A01` Người dùng, `A02` Lập trình viên, `A03` Hệ thống). |
| **Dữ liệu nhạy cảm** | Dữ liệu ảnh người dùng chỉ được xử lý tạm thời trong bộ nhớ RAM (in-memory buffer) để trích xuất toạ độ landmark và giải phóng ngay; **tuyệt đối không lưu trữ ảnh** xuống ổ đĩa, đảm bảo quyền riêng tư. |
| **Tấn công cạn kiệt tài nguyên** | Giới hạn giải phóng bộ nhớ ngay sau khi inference hoàn tất. (Validation mime-type và dung lượng tối đa 5 MB sẽ được thắt chặt ở `US-009`). |

## 10. Audit Impact

- Ghi log mức `INFO` cho mỗi request `/predict` thành công: Ký tự dự đoán, độ tin cậy, thời gian xử lý pipeline (latency tính bằng ms).
- Ghi log mức `WARNING` khi ảnh không nhận diện được bàn tay hoặc khuôn mặt.
- Ghi log mức `ERROR` khi giải mã ảnh thất bại hoặc model inference gặp exception.
- Không ghi nội dung ảnh nhị phân vào log để tránh tràn ổ đĩa.

## 15. Risks & Mitigation

| Rủi ro | Mức độ | Biện pháp giảm thiểu |
|---|---|---|
| **R-1: Lệch toạ độ giữa MediaPipe JS và Python** | Critical | **Đã xóa bỏ hoàn toàn** bằng cách thực thi MediaPipe Python server-side đúng như mô tả trong backlog. |
| **R-2: Lệch hướng bàn tay do không lật gương (BR-007)** | High | Đảm bảo `cv2.flip(image, 1)` được gọi ngay sau khi giải mã ảnh và trước khi đưa vào MediaPipe. |
| **R-3: Sai lệch tiền xử lý ResNet50 (BR-006)** | High | Dùng trực tiếp `keras.applications.resnet50.preprocess_input` (Caffe style), nghiêm cấm chia 255. |
| **R-4: Khởi tạo MediaPipe lặp đi lặp lại làm tăng latency** | Medium | Khởi tạo thể hiện `Hands` và `FaceMesh` ở mức module hoặc lifespan, tái sử dụng qua các request thay vì khởi tạo lại trong mỗi request. |
