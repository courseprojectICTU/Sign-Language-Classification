## 1. Mục tiêu

- **Vấn đề cần giải quyết:** Khi Container App scale về 0, request dự đoán đầu tiên có thể phải chờ backend cold start.
- **Kết quả mong đợi:** Trình duyệt bắt đầu gọi health endpoint ngay khi ứng dụng trang được tải, song song với lúc người dùng chuẩn bị ảnh.
- **Phạm vi:** Một GET nền đến `/health`, sử dụng API base URL cấu hình sẵn; không chặn render hoặc thao tác người dùng; bỏ qua lỗi warm-up.
- **Ngoài phạm vi:** Thay đổi backend, retry/polling, trạng thái loading riêng, thay đổi cấu hình min replicas, hoặc bảo đảm cold start được che hoàn toàn.

## 3. Existing Architecture

- **Backend:** FastAPI tại `src/vsl/service.py`, với endpoint `GET /health`.
- **Frontend:** Trang HTML tĩnh trong `web/`; `web/index.html` nạp `config.js` đồng bộ và `app.js` bằng `defer`.
- **Cấu hình API URL:** `window.VSL_CONFIG.apiBaseUrl` do `web/config.js` cung cấp.
- **Module liên quan:** `web/app.js`, `web/config.js`, `web/index.html`.
- **Cách chạy hiện tại:** Phục vụ thư mục `web/` qua static host; backend độc lập.
- **Quy ước lỗi:** Lỗi fetch trong các thao tác người dùng được hiển thị; lỗi warm-up phải được bỏ qua và không tác động giao diện.

## 6. Proposed API Changes

### 6.1. Frontend gọi `GET /health` (tái sử dụng)

- **Method:** `GET`
- **Endpoint:** `${window.VSL_CONFIG.apiBaseUrl}/health`
- **Purpose:** Khởi phát request đến service khi trang bắt đầu tải.
- **Authentication:** Public; không gửi credential.
- **Authorization:** A01; endpoint health hiện tại public.
- **Path Parameters:** Không có.
- **Query Parameters:** Không có.
- **Request Body:** Không có.
- **Response:** Bất kỳ response nào cũng không được hiển thị hoặc chặn giao diện.
- **HTTP Status:** Frontend không diễn giải status cho tính năng này.
- **Validation:** Chỉ gọi khi API base URL là chuỗi không rỗng.
- **Business Rules:** BR-019.
- **Error Cases:** Network error, CORS error, timeout hoặc HTTP error được bỏ qua; không retry.

## 7. Business Flow

```text
Browser tải HTML
  -> config.js thiết lập API base URL
  -> app.js bắt đầu thực thi (defer, sau khi HTML parse)
  -> gửi GET /health bất đồng bộ
  -> tiếp tục render và nhận thao tác người dùng, không chờ response
  -> bỏ qua lỗi của request warm-up
```

## 17. Implementation Handoff

- **Backend nhận:** Reuse `GET /health`; không đổi endpoint, response hoặc backend.
- **Frontend nhận:** Khi `app.js` bắt đầu chạy, gọi một lần `${apiBaseUrl}/health` dạng GET; không await; không gửi body/credential; bỏ qua mọi lỗi; không tạo UI warm-up.
- **Tester nhận:** Kiểm tra request xuất hiện sau page navigation và trước thao tác người dùng; mô phỏng lỗi để xác nhận trang vẫn dùng được.
- **Điều kiện bắt đầu code:** US-022 đã có trên `develop`; phạm vi US-023 được chủ dự án yêu cầu triển khai.
