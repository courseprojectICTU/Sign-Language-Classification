# CLI Design — US-031 Rollback backend bằng traffic split và diễn tập

> **Trạng thái:** `ANALYSIS_READY` — script an toàn được chuẩn bị; chưa diễn tập production
> **Epic:** `EPC-08` · **Nhánh:** `feature/US-031` · **Ngày:** 2026-11-07
> **Business Rule:** BR-022 (Rehearsed Rollback)
>
> Backend thực tế dùng Azure Container Apps, không phải Cloud Run. Azure CLI chưa cài
> trong môi trường phát triển; không truy cập hoặc thay đổi traffic cloud trong US này.

---

## 1. Mục tiêu

- Xác định revision Azure Container Apps đang nhận traffic và revision active liền trước.
- Mặc định chỉ chạy ở chế độ dry-run; chỉ đổi traffic khi operator truyền `--apply` cùng
  các xác nhận revision/SHA bắt buộc.
- Khi apply, đưa 100% traffic tới revision trước, xác nhận traffic và kiểm tra `/health`
  cùng `/version`.
- Ngoài phạm vi: Cloud Run, deploy pipeline tự động, thay đổi revision mode, tự tạo revision
  mới hoặc diễn tập production không có phê duyệt.

## 3. Existing Architecture

- Tài liệu bàn giao ghi backend staging chạy trên Azure Container Apps, app `vsl-api`,
  resource group `rg-vsl-staging`, không phải Google Cloud Run.
- Repo không có cấu hình Cloud Run, IaC quản lý revision hoặc deployment workflow.
- Azure Container Apps hỗ trợ revision traffic splitting; cấu hình multiple active revisions
  và số revision production hiện tại chưa được xác minh.
- Azure CLI không cài trong máy này; không có bằng chứng về hai revision production hoặc
  quyền truy cập subscription.

## 6. Proposed API Changes

### 6.1. CLI `scripts/rollback.py`

- **Purpose:** Dry-run hoặc rollback một Azure Container App cụ thể.
- **Arguments:** `--resource-group`, `--app-name` bắt buộc; `--subscription` tùy chọn;
  `--apply` để cho phép thay đổi traffic; khi apply bắt buộc `--target-revision`,
  `--expected-current-revision`, `--expected-sha`, `--url`.
- **Dry-run:** Mặc định; chỉ đọc Azure metadata và in revision hiện tại, target đề xuất
  cùng tỷ lệ traffic hiện tại. Không gọi lệnh ghi.
- **Safety validation:** Yêu cầu revision mode `Multiple`, đúng một revision đang nhận
  100% traffic, tối thiểu hai revision active, target active và không nhận traffic,
  target khớp revision trước được suy ra, và current revision khớp xác nhận operator.
- **Apply:** Gửi `az containerapp ingress traffic set --revision-weight <target>=100 <current>=0`,
  đọc lại traffic để xác nhận target 100% và current 0%, rồi kiểm tra HTTP 200 của
  `/health` (`model_loaded=true`) và `/version` (`git_sha` khớp SHA của target).
- **Exit status:** `0` khi dry-run hợp lệ hoặc apply và xác minh thành công; khác `0`
  khi precondition/CLI/traffic/HTTP/SHA thất bại.
- **Error behavior:** Fail closed, nêu rõ bước thất bại; không tự đoán nếu Azure trả metadata
  không đủ hoặc traffic đang split không đơn nhất.
- **Security:** Không nhận secret; Azure CLI dùng danh tính đã đăng nhập. Không ghi token.

Ví dụ dry-run:

```powershell
python scripts/rollback.py --resource-group <resource-group> --app-name <container-app>
```

Apply chỉ sau khi operator kiểm tra dry-run và xác nhận revision:

```powershell
python scripts/rollback.py `
  --resource-group <resource-group> `
  --app-name <container-app> `
  --expected-current-revision <bad-revision> `
  --target-revision <previous-revision> `
  --expected-sha <previous-git-sha> `
  --url https://<container-app-fqdn> `
  --apply
```

### 6.2. Azure CLI commands used

```text
az containerapp show --query properties.configuration.activeRevisionsMode
az containerapp revision list
az containerapp ingress traffic show
az containerapp ingress traffic set --revision-weight <target>=100 <current>=0
```

`--revision-weight` là cú pháp hiện hành; script không tự chuyển app sang multiple revision
mode. Xem [Microsoft CLI reference: traffic](https://learn.microsoft.com/en-us/cli/azure/containerapp/ingress/traffic)
và [revision](https://learn.microsoft.com/en-us/cli/azure/containerapp/revision).

## 7. Business Flow

```text
Đọc revision mode, active revisions và traffic hiện tại (read-only)
  -> fail nếu mode không phải Multiple, dữ liệu thiếu hoặc traffic không đơn nhất
  -> chọn revision active gần nhất trước revision hiện tại
  -> dry-run: in target và dừng, không đổi cloud
  -> --apply: yêu cầu operator xác nhận current/target/SHA/URL
  -> set target=100%, current=0%
  -> đọc lại traffic và xác nhận /health + /version
```

Deployment workflow tương lai chỉ có thể tự rollback sau khi US-029 xác định trigger,
revision URL và cách gọi script; không được coi dry-run là rehearsal.

## 8. Security

| Mục | Giá trị |
|---|---|
| Authentication | Azure CLI identity do operator đăng nhập |
| Authorization | Azure role có quyền đọc revision/traffic; quyền ghi chỉ cần khi `--apply` |
| Target scope | Resource group và app bắt buộc truyền, không dùng default production |
| Change guard | Dry-run mặc định; `--apply` cộng xác nhận current/target/SHA/URL |
| Secret | Không lưu hoặc in token/credential |
| Shell | Gọi subprocess bằng argument list, không dùng shell command string |

## 10. Audit Impact

- CLI in revision hiện tại, target, weights trước/sau, SHA kỳ vọng và kết quả verification.
- Azure Activity Log vẫn là nguồn audit cho thao tác control-plane.
- Không ghi credentials hoặc response body ảnh.

## 11. Data Model Impact

Không có database hoặc migration. Revision/traffic metadata được đọc trực tiếp từ Azure CLI.

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| Chọn sai revision ổn định | Người dùng tiếp tục gặp lỗi hoặc bị rollback quá sâu | Dry-run, xác nhận target/current, kiểm tra SHA; dừng khi dữ liệu mơ hồ |
| Revision mode là Single | Không thể giữ revision cũ để chia traffic | Script không tự đổi mode; operator chuẩn bị Multiple mode riêng |
| Không có hai revision production | Không có target rollback hợp lệ | Không apply; tạo/giữ revision theo quy trình được duyệt trước |
| Verification sau khi chuyển traffic fail | Traffic có thể đã đổi nhưng app chưa sẵn sàng | Báo lỗi rõ và yêu cầu xử lý thủ công; không tự quay về revision lỗi |

## 17. Implementation Handoff

- **Backend nhận:** Không đổi API; dùng `/health` và `/version` để xác minh.
- **DevOps nhận:** Cài Azure CLI, xác thực Azure, xác nhận resource group/app, revision mode,
  ít nhất hai revision active và SHA của bản ổn định.
- **Tester nhận:** Chạy unit tests; rehearsal thật chỉ sau khi được cho phép và ghi lại thời gian.
- **Điều kiện apply:** Review dry-run, xác nhận current/target/SHA/URL và truyền `--apply`.
- **Trạng thái nghiệm thu:** Chưa có rehearsal production và chưa tự rollback từ pipeline.
