> **Epic:** `EPC-03` · **Nhánh:** `feature/US-011` · **Ngày:** 2026-11-10
> **Actor:** A02 — Nhóm phát triển · **Business Rule:** BR-012
> **Dependency:** US-010 — Docker image build thành công.
>
> **API docs: N/A cho public HTTP API** — US-011 không thêm endpoint. File này ghi contract cho model artifact, converter, parity test và fallback. Dữ liệu backlog được đọc từ bốn sheet ngày 2026-11-10.
>
> **Môi trường kiểm chứng hiện tại:** Python 3.12.10 có TensorFlow/Keras package nhưng import TensorFlow bị Windows Application Control chặn tại `_pywrap_tf2`; `tf2onnx`, `onnx` và `onnxruntime` chưa cài. Chưa có kết quả conversion/parity/benchmark.

## 1. Mục tiêu

- **Vấn đề:** TensorFlow/Keras làm tăng cold-start và kích thước container; backlog ước tính TensorFlow khoảng 20 giây và ONNX khoảng 5 giây, nhưng cần đo thay vì coi đây là kết quả.
- **Kết quả mong đợi:** Xuất model H5 qua SavedModel sang ONNX; xác minh ONNX Runtime nạp được; so sánh xác suất Keras/ONNX trên cùng 23 heatmap và ghi size/timing thực tế.
- **Phạm vi:** TSK-017 (export) và TSK-018 (parity); giữ BR-006 preprocessing Caffe; tạo ADR fallback nếu conversion hoặc parity thất bại.
- **Ngoài phạm vi:** Không đổi heatmap, model weights, thứ tự nhãn, preprocessing, endpoint hoặc pipeline đang dùng trước khi có parity pass và được chủ dự án duyệt.

## 3. Existing Architecture

Đối chiếu repository ngày 2026-11-10:

- **Model:** `train/vsl_cnn_pose_keras.h5`, 137,042,364 bytes; Git LFS quản lý `*.h5`.
- **Input/output contract:** ResNet50 nhận batch heatmap `(N, 224, 224, 3)` theo thứ tự RGB-equivalent channels của heatmap; output có 23 lớp theo `src/vsl/labels.py`.
- **Inference:** `src/vsl/service.py` gọi `create_heatmap`, rồi `preprocess_heatmap`, hiện dùng `keras.applications.resnet50.preprocess_input` kiểu Caffe.
- **Samples:** `data/anphabet/<letter>/1.csv` cho 23 nhãn, mỗi file có 93 tọa độ landmark theo BR-001.
- **Container:** `Dockerfile` cài TensorFlow/Keras từ `requirements-runtime.txt` và copy model H5. Docker CLI không có trong môi trường hiện tại.
- **ONNX tooling:** Không có exporter, ONNX artifact hay parity test hiện hữu. Interpreter hiện tại thiếu `tf2onnx`, `onnx`, `onnxruntime`; TensorFlow import bị policy hệ điều hành chặn.

### 6.2. Model artifact and parity contract

- **Source artifact:** `train/vsl_cnn_pose_keras.h5`; không sửa hoặc ghi đè model nguồn.
- **Intermediate:** SavedModel tạo trong thư mục tạm hoặc path chỉ định, không commit vào repository mặc định.
- **Output:** `models/model.onnx` theo yêu cầu; exporter phải hỗ trợ output path và không ghi đè khi chưa được yêu cầu (default hành vi an toàn sẽ được chốt ở implementation).
- **Conversion:** Load Keras model, export SavedModel có input signature batch động, sau đó chạy `tf2onnx` converter. Ghi rõ version converter, opset và input/output names trong output/log.
- **Preprocessing:** Cả hai model nhận cùng batch heatmaps sau đúng BR-006 Caffe `preprocess_input`; tuyệt đối không scale `/255`.
- **Parity:** So sánh tensor xác suất cùng shape trên 23 mẫu; yêu cầu `max(abs(keras_pred - onnx_pred)) < 1e-4` và `argmax` bằng nhau cho từng sample.
- **Fallback:** Nếu conversion, ONNX load hoặc parity fail, không chuyển service/runtime sang ONNX; ghi `docs/decisions/US-011-onnx-fallback.md`, giữ TensorFlow path và xác minh image vẫn build.
- **Runtime migration:** Chỉ xem xét thay TensorFlow runtime bằng ONNX Runtime sau khi AC-011-01 pass, có size/build measurements và chủ dự án duyệt thay đổi Docker/dependencies/service. Đây không phải điều kiện để tự ý thay pipeline.

## 7. Business Flow

```text
23 CSV mẫu (mỗi nhãn 1.csv)
  → đọc 93 landmark values
  → create_heatmap thành uint8 (224,224,3)
  → stack thành batch (23,224,224,3)
  → ResNet50 preprocess_input Caffe, dùng chung cho cả hai backend
  → Keras model inference ───────────────────┐
  → SavedModel export → tf2onnx → ONNX Runtime ├→ so output, max diff và argmax
                                               └→ ghi size/timing/evidence
      ├─ Parity pass: báo cáo kết quả; runtime switch chỉ sau review/approval
      └─ Conversion/parity fail: ADR ghi lý do, giữ TensorFlow, kiểm tra build
```

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| TensorFlow/Keras 3 SavedModel export và `tf2onnx` compatibility | Export có thể lỗi trước khi tạo ONNX | Pin và kiểm thử toolchain; giữ nguyên H5; khi fail tạo ADR, không thay runtime |
| ONNX op conversion/numerical drift vượt `1e-4` | AC-011-01 không đạt, phân loại có thể khác | So full output tensors và argmax trên 23 mẫu; không hạ ngưỡng để làm test xanh |
| Sai preprocessing/heatmap khiến parity giả hoặc inference khác | So sánh không đại diện production | Dùng cùng `create_heatmap` và Caffe `preprocess_heatmap`; cấm `/255`; verify BR-006 |
| ONNX artifact lớn hoặc không tái lập | Repo/image tăng size, pipeline build thất bại | Đo trước; artifact retention/LFS decision trước khi commit; mặc định build-time export/temp |
| Runtime/CPU threading khác môi trường | Timing dao động và có thể nhầm cold start | Ghi runtime, device/thread settings và tách model-load, inference, container cold-start timing |
| Local Windows policy chặn TensorFlow DLL | Không chạy được conversion/parity local | Thử Linux CI/runner; không suy ra conversion failure từ policy local; báo trạng thái validation chính xác |

## 17. Implementation Handoff

- **Model/ML:** Preserve H5 and implement reproducible SavedModel → ONNX export; report conversion versions/signatures/hash/size.
- **Tester:** Use the 23 first-sample CSVs, produce heatmaps through the shared helper, apply BR-006 Caffe preprocessing once, feed identical batch to both models, assert `<1e-4` and identical argmax.
- **Fallback owner:** If export or parity fails, add ADR with observed error/diff and evidence; keep TensorFlow pipeline and prove baseline/image build remain valid.
- **Reviewer:** Confirm Q1–Q5 decisions, artifact policy, exact benchmark interpretation and that no unrelated contributor code was modified.
- **Completion:** AC-011-01 passes with recorded outputs and size/timing, or AC-011-02 is evidenced with fallback ADR; regression and all CI gates pass; owner accepts results.
