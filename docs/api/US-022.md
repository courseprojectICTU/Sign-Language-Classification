## 1. Mục tiêu

- **Vấn đề cần giải quyết:** Người dùng cuối chưa có giao diện trình duyệt để gửi ảnh bàn tay đến dịch vụ dự đoán.
- **Kết quả mong đợi:** Trang tĩnh trong `web/` cho phép chọn ảnh hoặc chụp bằng camera, xem trước ảnh, gửi ảnh đến API hiện có và hiển thị ký tự dự đoán cùng độ tin cậy. Trang hiển thị trạng thái đang xử lý trong khi API chưa trả lời.
- **Phạm vi:** Giao diện người dùng, request/response phía trình duyệt, preview ảnh, camera capture, loading, kết quả và danh sách/hướng dẫn 23 ký tự được hỗ trợ. Danh sách web được sinh từ nguồn chân lý Python BR-003.
- **Ngoài phạm vi:** Tạo endpoint backend mới; warm-up `GET /health` khi tải trang (US-023); triển khai Cloudflare Pages (US-024); cấu hình CORS phía backend (US-025); thay đổi pipeline suy luận hoặc lưu ảnh/lịch sử.

## 3. Existing Architecture

- **Backend:** FastAPI service tại `src/vsl/service.py`; có `GET /health`, `GET /version` và `POST /predict`.
- **Frontend:** Chưa có thư mục `web/` hoặc mã giao diện trong nhánh `develop` tại thời điểm phân tích.
- **Module liên quan:** `src/vsl/service.py` định nghĩa `PredictResponse`; `src/vsl/labels.py` là nguồn chân lý cho 23 nhãn tiếng Việt. `web/labels.json` là asset sinh ra từ nguồn này bằng `scripts/generate_web_labels.py`.
- **Cách chạy hiện tại:** Backend chạy bằng Uvicorn; chưa có lệnh hoặc máy chủ frontend trong repo.
- **Response/error hiện có:** `/predict` nhận trường multipart `file`; thành công trả `status: "ok"`, `letter`, `confidence`, `top_k`; thiếu landmark trả `status: "no_hand"` hoặc `"no_face"` với HTTP 200; ảnh không giải mã được trả HTTP 400; model chưa sẵn sàng trả HTTP 503.
- **Cấu hình API URL:** ADR-001 ghi backend công khai là `https://vsl-api.wittyground-02475ae2.eastasia.azurecontainerapps.io`. Frontend đọc `window.VSL_CONFIG.apiBaseUrl` từ `web/config.js`; mặc định dùng URL staging này, và US-024 có thể thay cấu hình khi triển khai. Không đưa credential vào frontend.

## 6. Proposed API Changes

### 6.1. Tích hợp frontend với `POST /predict` (reuse, không thay đổi backend)

- **Method:** `POST`
- **Endpoint:** `/predict` tại API base URL được cấu hình cho frontend.
- **Purpose:** Gửi ảnh được người dùng chọn hoặc chụp và nhận kết quả phân loại.
- **Authentication:** Public; không gửi token hoặc thông tin xác thực.
- **Authorization:** A01 (người dùng cuối).
- **Path Parameters:** Không có.
- **Query Parameters:**
  - `top_k`: Client không truyền; backend dùng mặc định `3`.
  - `flip`: Boolean tùy chọn, mặc định `false`. Frontend gửi `flip=true` khi người dùng bật nút lật ảnh và `flip=false` khi tắt. Backend dùng lựa chọn này để lật ngang ảnh trước khi trích xuất landmark.
- **Request Body:** `multipart/form-data`, một trường `file` chứa ảnh. Khi dùng `FormData`, trình duyệt tự tạo `Content-Type` kèm boundary; client không tự đặt header này.
- **Response thành công:** Theo schema hiện có:

  ```json
  {
    "status": "ok",
    "detected": true,
    "letter": "a",
    "confidence": 0.9854,
    "top_k": [
      {"letter": "a", "confidence": 0.9854},
      {"letter": "c", "confidence": 0.0082},
      {"letter": "d", "confidence": 0.0031}
    ],
    "has_hand": true,
    "has_face": true,
    "model_version": "v1.0"
  }
  ```

- **Hiển thị kết quả:** Với `status: "ok"` và `detected: true`, hiển thị `letter` và `confidence` dưới dạng phần trăm (`confidence × 100`). Không yêu cầu hiển thị `top_k`.
- **Không phát hiện đủ landmark:** HTTP 200 với `detected: false`, `letter: null`, `status` là `"no_hand"` hoặc `"no_face"` và `message`; hiển thị hướng dẫn từ response, không trình bày như lỗi kết nối.
- **HTTP Status:** `200`, `400`, `503` theo hợp đồng hiện có; lỗi mạng/CORS không có HTTP response đọc được.
- **Validation:** Chỉ gửi ảnh sau khi người dùng chọn hoặc chụp; backend vẫn là nguồn kiểm tra ảnh có giải mã được. `accept="image/*"` (nếu dùng) chỉ là gợi ý cho bộ chọn tệp, không thay thế validation server.
- **Điều khiển preview:** Nút lật ảnh chỉ bật sau khi có ảnh. Khi bật, preview được lật ngang và nút phản ánh trạng thái qua `aria-pressed`; cùng lựa chọn được truyền bằng query `flip` khi dự đoán. Không sửa dữ liệu ảnh gốc ở trình duyệt.
- **Business Rules:** BR-018 cho request browser cross-origin; ảnh chỉ được gửi khi người dùng yêu cầu dự đoán; không lưu ảnh hoặc lịch sử.
- **Error Cases:** HTTP 400/503 hiển thị thông báo có thể hiểu được; lỗi mạng/CORS hiển thị trạng thái lỗi và cho phép thử lại. Trong lúc request còn chờ, giữ loading state và không coi việc chờ cold start là lỗi.

### 6.2. API base URL phía client

- Không tạo endpoint cấu hình mới. Frontend đọc API base URL từ một giá trị cấu hình client có thể thay thế; URL staging hiện được ghi trong ADR-001.
- Tên cấu hình: `window.VSL_CONFIG.apiBaseUrl`; giá trị là base URL không có dấu `/` cuối. Client ghép với `/predict`.
- `web/config.js` khởi tạo cấu hình mặc định bằng URL staging ở mục 3. Môi trường triển khai có thể thay giá trị này mà không sửa luồng request/response.
- Giá trị cấu hình không phải secret. Không đặt token/credential trong HTML, JavaScript, query string hoặc local storage.
- US-024 cần cung cấp giá trị phù hợp môi trường khi triển khai Cloudflare Pages; không thay đổi hợp đồng `/predict`.

### 6.3. Danh sách ký tự tĩnh

- **Nguồn:** `src/vsl/labels.py:VIETNAMESE_ALPHABET` theo BR-003.
- **Asset:** `web/labels.json`, mảng JSON gồm 23 chuỗi theo đúng thứ tự trong tuple Python.
- **Sinh/cập nhật:** Chạy `python scripts/generate_web_labels.py` để ghi lại asset từ nguồn Python. Không duy trì một danh sách nhãn viết tay trong JavaScript.
- **Tiêu thụ:** Frontend tải `labels.json` cùng origin và render danh sách hỗ trợ. Nếu asset không tải/không hợp lệ, hiển thị thông báo thay vì âm thầm dùng danh sách fallback.
- Đây là tài nguyên tĩnh của frontend, không phải endpoint backend mới; không làm thay đổi API `/predict`.

## 7. Business Flow

```text
Người dùng mở trang tĩnh
  → frontend tải web/labels.json và hiển thị danh sách ký tự hỗ trợ
  → chọn tệp ảnh hoặc cấp quyền camera và chụp ảnh
  → frontend hiển thị preview; người dùng có thể bật/tắt lật ngang
  → người dùng bấm Dự đoán
  → frontend hiển thị trạng thái đang xử lý
  → POST /predict?flip=true|false với multipart/form-data, trường file
  → trong thời gian chờ backend khởi động, giữ nguyên trang và trạng thái loading
  → HTTP 200, status=ok, detected=true: hiển thị letter và confidence
  → HTTP 200, detected=false: hiển thị message/hướng dẫn từ API
  → HTTP 400/503 hoặc lỗi mạng: hiển thị thông báo lỗi có thể hiểu được
```

US-022 không tự gọi `/health` lúc tải trang; đó là hành vi của US-023. Ảnh chỉ được gửi sau thao tác Dự đoán và không được ghi vào server-side storage, lịch sử hay telemetry.

## 17. Implementation Handoff

- **Backend nhận:** Không đổi backend/API trong US-022. API consumer dùng `POST /predict` hiện có; CORS/allowlist theo BR-018 thuộc US-025.
- **Frontend nhận:** Đọc API base URL từ cấu hình client; tải nhãn tĩnh được sinh từ `src/vsl/labels.py`; gửi `FormData` với key `file` và query `flip` theo nút lật ảnh; không tự đặt multipart `Content-Type`; xử lý các trạng thái `ok`, `no_hand`, `no_face`, lỗi HTTP và lỗi mạng; không lưu ảnh/lịch sử.
- **Tester nhận:** Viết Playwright tests trước source cho AC-022-01/02; test upload/preview, camera, nội dung 23 nhãn và lỗi. Chạy browser matrix Chrome/Edge/Firefox cùng viewport nhỏ 375×812. Dùng API stub cho test có thể lặp lại; ảnh live API còn thiếu.
- **Điều kiện bắt đầu test/code:** Chủ dự án duyệt hợp đồng này; sau đó viết test trước code và chứng minh test đỏ. Không bắt đầu test khi trạng thái còn chờ duyệt.
