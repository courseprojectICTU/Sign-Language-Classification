## 1. Mục tiêu

- **Vấn đề:** Sau deploy hoặc rollback, nhóm phát triển không xác định được chính xác model và commit đang phục vụ.
- **Kết quả:** `GET /version` trả `model_version`, `git_sha`, `build_time`; response có giá trị fallback an toàn khi chạy local hoặc thiếu metadata build.
- **Phạm vi:** Thêm endpoint, response model Pydantic, test cho metadata môi trường và fallback, cập nhật tài liệu.
- **Ngoài phạm vi:** Docker image, CI/CD build pipeline, triển khai Cloud Run. Repo hiện chưa có Dockerfile; wiring `ARG GIT_SHA`/`ENV GIT_SHA` sẽ được thực hiện khi Dockerfile được tạo ở US-010.

## 6. Proposed API Changes

### 6.1. `GET /version`

- **Method:** `GET`
- **Endpoint:** `/version`
- **Purpose:** Trả metadata định danh model và source/build đang chạy.
- **Authentication:** Public, nhất quán các endpoint hiện có.
- **Authorization:** Không yêu cầu role.
- **Path Parameters:** Không.
- **Query Parameters:** Không.
- **Request Body:** Không.
- **Response Model:** `VersionResponse` (Pydantic), gồm ba trường bắt buộc dạng string.
- **HTTP Status:** `200 OK`.
- **Validation / precedence:**
  - `model_version`: `VSL_MODEL_VERSION` → `app.state.model_version` → `"v1.0"`.
  - `git_sha`: `GIT_SHA` → `git rev-parse HEAD` trong local checkout → `"unknown"` nếu Git không khả dụng.
  - `build_time`: `BUILD_TIME` hợp lệ → timestamp UTC tại lúc tạo service app.
  - `build_time` luôn là ISO 8601 UTC, hậu tố `Z`.
- **Business Rules:** BR-009 — Git SHA là định danh bất biến dùng truy vết image/revision; không dùng tag `latest` làm định danh.
- **Error Cases:** Endpoint vẫn trả `200` với fallback metadata an toàn khi biến môi trường hoặc Git checkout không có.

Ví dụ:

```bash
curl http://localhost:8000/version
```

```json
{
  "model_version": "v1.0",
  "git_sha": "abc1234",
  "build_time": "2026-11-02T10:15:30Z"
}
```

Docker build sau này cần khai báo `ARG GIT_SHA` và `ENV GIT_SHA=${GIT_SHA}`; ở bước build truyền SHA của commit (ví dụ `--build-arg GIT_SHA=<commit-sha>`). Việc tạo Dockerfile thuộc US-010, không nằm trong US-008.

## 7. Business Flow

```text
GET /version
  -> đọc VSL_MODEL_VERSION, nếu thiếu dùng app.state.model_version hoặc v1.0
  -> đọc GIT_SHA
       -> nếu thiếu, thử git rev-parse HEAD
       -> nếu Git không có/không chạy được, trả unknown
  -> dùng BUILD_TIME hợp lệ hoặc thời điểm tạo service app UTC
  -> trả VersionResponse JSON, HTTP 200
```

## 15. Risks

| Rủi ro | Ảnh hưởng | Giảm thiểu |
|---|---|---|
| `GIT_SHA` không được truyền vào image | Revision khó truy vết | Fallback local/`unknown`; Dockerfile US-010 sẽ wiring `ARG`/`ENV`; deploy pipeline phải truyền SHA |
| Build time không hợp lệ | Metadata không đúng UTC | Validate timestamp; fallback sang thời điểm tạo app UTC |
| Model version bị cấu hình rỗng | Response thiếu định danh | Fallback qua app state rồi `v1.0` |

## 16. Open Questions

Không còn câu hỏi chặn cho endpoint. Docker build argument sẽ được áp dụng khi Dockerfile được tạo trong US-010.

## 17. Implementation Handoff

- **Backend:** Thêm `VersionResponse`, route `GET /version`, đọc `GIT_SHA`/`VSL_MODEL_VERSION`/`BUILD_TIME` với fallback an toàn.
- **DevOps:** Khi có Dockerfile ở US-010, khai báo `ARG GIT_SHA`, `ENV GIT_SHA=${GIT_SHA}` và truyền commit SHA lúc build.
- **Tester:** Kiểm tra HTTP 200, đủ ba trường, giá trị env, fallback và OpenAPI schema.
- **Điều kiện bắt đầu code:** Hợp đồng theo yêu cầu US-008 của Chủ dự án ngày 2026-11-02; viết test trước implementation.
